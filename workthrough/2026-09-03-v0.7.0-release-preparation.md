# v0.7.0 stable release preparation

## Overview

This change prepares the exact source contract for the next stable devbox release. The bundle moves
from v0.6.0 to v0.7.0 because the accumulated work adds substantial backwards-compatible WSL
Desktop capabilities and changes the development and release delivery path, while preserving the
15-application product and 32-public/31-manifest-declared asset contracts.

The preparation synchronizes every changed application's frontend, Cargo, Tauri and packaged-smoke
version, advances installer acceptance to the real v0.6.0 baseline, records release notes and an
execution plan, regenerates dependency evidence, and audits the shared and per-application
documentation. It deliberately does not claim that v0.7.0 is public yet: v0.6.0 remains Latest
until an exact-main Windows candidate passes packaged runtime and update/rollback acceptance and
the same candidate is promoted through an annotated tag.

## Context

### Why this is a minor release

The source since v0.6.0 includes WSL Desktop in-app dialogs and settings, keyboard-oriented
tab/pane navigation, resizable topology, WebGL fallback, safer terminal interaction, multiplexer
rediscovery, marker-owned Bash/Zsh cwd reporting, active-first exact workspace restoration and
Quick Summon/tray behavior. It also replaces routine full-workspace CI with an affected dependency
graph, changes stable publication to promote an already accepted candidate without recompilation,
and splits the remaining Windows package work into three bounded five-app shards.

These are backwards-compatible features and workflow improvements rather than breaking API or
data-format changes. A bundle-level `v0.7.0` tag therefore communicates the scope more accurately
than a v0.6.x patch. Individual applications retain independent semantic versions and only advance
when their shipped source changed.

### Installed-system acceptance

Issue #518 was the authoritative remaining post-v0.6.0 physical checklist. On 2026-09-03 the user
confirmed the installed WSL Desktop can discover user-local Cargo-installed zellij, attach both new
and existing sessions, disconnect and reconnect, preserve zellij/Codex processes, and restore the
terminal workspace. The evidence was recorded on the issue and it was closed as completed.

Legacy identifier migration and the Life Log absorption migration remain enabled throughout
v0.7.0. Their removal will be reconsidered only after v0.7.x adoption and installed-data read-back,
so this release does not turn a successful physical observation into an unsafe migration cleanup.

### 2. Advance release and installer contracts

`windows-installer-acceptance-config.json` now uses the public v0.6.0 tag and its peeled source
commit `d2fa25a0a1f087459838449daded00c0b09764b4` as the update/rollback baseline. Its contract test
was updated in the same change. The v0.7.0 plan requires an exact-main candidate built as three
five-app shards, independent assembly of the existing full asset contract, packaged runtime smoke,
and v0.6.0-to-v0.7.0 update/rollback before any tag is created.

Stable publication will then validate candidate provenance and SHA-256 metadata and promote those
same 32 files without rebuilding all 15 applications. No release candidate tag is introduced.

### 3. Record release notes and dependency evidence

`CHANGELOG.md` now has an empty Unreleased section followed by a complete dated v0.7.0 section. It
documents the user-visible terminal changes, draft/listener stability fixes, affected CI, candidate
promotion, package sharding, exact app version matrix and installed #518 evidence. The repository's
release-note extractor accepts the section as a non-empty `v0.7.0` payload.

The official dependency notice generator refreshed `THIRD_PARTY_NOTICES.md` from the updated lock
state. No dependency inventory changed; only the recorded Cargo lock hash changed.

- Cargo lock SHA-256: `aec85df4631d0f7ebb0d8d4b6f0e6b4ca38fb9eed3b4fa164525e7b085a5db3d`
- Notice SHA-256: `e964b2b711a8b80e793a230d89e20581fe7874dcf841fa9c9d839297440f84a4`
- Notice size: 146,028 bytes
- Inventories: 732 Rust packages and 160 frontend runtime dependencies

The existing `glib 0.18.5` advisory remains an explicitly time-bounded exception through
2026-11-30. Tauri's compatible dependency line still has no patched resolver result, so this
release neither hides the open alert nor attempts an incompatible GTK stack upgrade.

### 4. Audit shared documentation

The shared-document review covered the root README, contributor instructions, conventions,
architecture, development guide, project catalog, roadmap, Windows guide, dependency policy,
current release plans/reports/specifications, all seven shared packages, and active cross-links.

Updates include:

- an explicit distinction between current main source and the still-public v0.6.0 Latest release;
- the complete 15-app, 13-crate and seven-package inventory;
- exact current application versions and product executable names, including `Code Pad.exe` and
  `Run Manager.exe`;
- the v0.7.0 WSL state, persistence, Quick Summon and release-efficiency boundaries;
- closure of #518 and clarification of historical statements that were pending only at the time
  their design or roadmap entries were written;
- a new README for `packages/mermaid-renderer`, the only shared package that lacked one, covering
  lazy initialization, strict rendering security, retry semantics, consumers and offline scope.

Historical, read-only proposals retain their original period-specific facts. In particular,
`docs/product-opportunities.md` still records old executable examples because rewriting them would
alter a completed 12-app proposal rather than correct an active contract.

### 5. Audit every application README

All 15 `apps/*/README.md` files were reviewed. API Playground, Devbox Launcher, Devbox Manager,
Log Lens, Port Manager, Webhook Lab and Workbench contained stale version or acceptance language
and were corrected. WSL Desktop already described the new terminal behavior in full. The remaining
seven app READMEs required no active-contract changes.

The audit confirms 15/15 application READMEs and 7/7 shared-package READMEs exist. A relative-link
scan found no missing targets in current Markdown documentation; historical workthrough snippets
were intentionally excluded because their paths are quoted evidence rather than live navigation.

WSL Desktop's initial bundle was 697,053 bytes raw and 200,841 bytes gzip, below its 755,000 and
220,000 byte limits. Its lazy WebGL chunk remained separate at 110,225 bytes raw and 29,794 bytes
gzip. During the Rust audit, frontend workspace concurrency and Cargo build jobs were both capped
at one; a live resource check showed about 12 GiB available memory rather than spawning all app
work simultaneously.

The first `verify:all` invocation stopped at the first frontend build because the new worktree had
no `node_modules` links (`tsc` was unavailable). `pnpm install --frozen-lockfile` restored the
workspace links from the existing package cache in 1.4 seconds without changing the lockfile. The
complete command was then rerun from the beginning and passed; the initial stop was an environment
bootstrap condition, not a product or test failure.

## Next steps

- Push this preparation as one cohesive release-boundary PR and require GitHub Actions CI success
  before merge.
- Dispatch the Windows candidate workflow against the exact merged main SHA and require all three
  package shards, assembly, packaged-smoke and installer update/rollback jobs to pass.
- Create and push annotated tag `v0.7.0` only for that accepted SHA, then verify that the Release
  workflow promotes the candidate without recompilation and publishes the exact asset contract as
  non-draft, non-prerelease Latest.
- Follow publication with a documentation-only evidence PR recording the exact tag object, peeled
  commit, workflow run ids, public release metadata and candidate/public digest comparison.
- Remove the dedicated worktrees, local and remote work branches, and temporary files only after
  each merged PR is confirmed clean and fully merged.
