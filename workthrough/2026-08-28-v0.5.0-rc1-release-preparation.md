# v0.5.0-rc1 Release Preparation

## Summary

This change prepares the completed v0.5.0 feature set for its first immutable Windows release
candidate without claiming that packaged acceptance or the stable release is complete. It aligns
the 11 applications that were still below their documented v0.5.0 target, preserves the four apps
already at target, refreshes the lockfile-derived third-party notice, and adds an explicit RC-to-
stable execution plan.

The resulting source inventory is 15 release applications, 45 matching version declarations, and
an expected GitHub Release of 32 assets: 15 portable executables, 15 NSIS installers,
`THIRD_PARTY_NOTICES.md`, and `release-manifest.json`. The manifest declares and hashes 31 assets;
the manifest itself is the only verification exception.

This workthrough documents source preparation and local verification only. The required PR CI,
`v0.5.0-rc1` tag, official Windows packages, independent asset verification, W1-W4 packaged
acceptance, and stable release remain later gates in the release plan.

## Context and release boundary

- Baseline source: `origin/main` at `fb16609ca7c3562f700edf755eea50ccf996f66f`.
- Latest stable at preparation time: `v0.4.2`.
- v0.5.0 milestone: all planned P1, P2, and selected P3 implementation issues are closed and their
  feature PRs are merged.
- New applications included in the 15-app matrix: Devbox Launcher 0.1.0 and Log Lens 0.1.0.
- Packaged Windows acceptance is intentionally not inferred from Linux builds, unit tests, prior
  feature CI, or the v0.4.2 H1 evidence.

The release plan keeps the project's native-first intent: frequently used core flows remain
available offline inside devbox, while WSL, Git, container engines, and remote APIs may require the
external target they explicitly manage. Optional external tools do not replace P1/P2 behavior.

## Verification

### Release metadata and dependency gates

Passed:

```text
bash .github/scripts/check-catalog.sh
custom v0.5.0 target check: 15 apps, 45 version sources, 15 release targets
python3 .github/scripts/test-extract-release-notes.py
python3 .github/scripts/extract-release-notes.py CHANGELOG.md v0.5.0-rc1
python3 .github/scripts/test-build-manifest.py
python3 .github/scripts/check-dependencies.py check
python3 .github/scripts/test-check-dependencies.py
cargo deny --locked check
pnpm audit --audit-level moderate
git diff --check
```

The release-note extractor returned only the new RC1 section. Dependency policy confirmed that
notices match both lockfiles. `cargo deny` reported only the policy-allowed duplicate-version
diagnostics and finished with advisories, bans, licenses, and sources all accepted. pnpm reported no
known vulnerabilities.

### Rust workspace

All commands used the existing Linux-native shared target
`/home/jihoon/.cache/targets/devbox` and at most two compile jobs:

```text
cargo test --workspace --locked -j 2
cargo check --workspace --locked -j 2
cargo clippy --workspace --all-targets --locked -j 2 -- -D warnings
cargo fmt --all -- --check
```

All application, shared-crate, integration, and doctest targets passed. The version-only app crate
rebuild completed without source warnings or clippy findings.

### Frontend workspace

`pnpm install --frozen-lockfile` reused all 311 packages from the existing store and downloaded
nothing. The first `pnpm test` used pnpm's default four-workspace concurrency. Devbox Launcher's
Vitest worker did not respond within 60 seconds while three other app suites started in parallel;
the recursive command stopped with a worker-start timeout, not a test assertion failure. No worker
from that attempt remained afterward.

The complete test matrix was rerun with one workspace at a time:

```text
pnpm --workspace-concurrency=1 -r test
```

Result: **144 test files and 1,222 tests passed**, including the Launcher suite that had timed out
during parallel startup. No functional failure remained.

The production matrix was also run sequentially:

```text
pnpm --workspace-concurrency=1 -r build
```

All 15 applications and the shared context-menu typecheck passed. Existing Vite warnings for large
API Playground, Developer Toolbox, Code Pad, Knowledge, and WSL Desktop chunks and API Playground's
mixed dynamic/static event import remained non-blocking; this version-only change introduced no new
bundle dependency or behavior.

## Resource handling

- C: free space was checked before, during, and after the local gates and remained approximately
  115GB, above the user-defined 100GB floor.
- No WSL sparse-disk compaction or empty-block return was performed.
- Rust reused one existing C:-backed WSL target instead of creating another target tree. The shared
  target grew while recompiling version-stamped app crates, but the C: free-space floor remained
  satisfied.
- Frontend `node_modules` links and all `dist` output were created in the E: worktree.
- Cargo and pnpm operations were run sequentially; Rust compile concurrency was capped at two and
  frontend workspace concurrency was reduced to one after the worker-start timeout.

## Remaining gates

This preparation is not the release completion point. Remaining mandatory work is:

1. root review of the full diff, release-preparation commit and PR;
2. all required GitHub Actions jobs passing before merge;
3. annotated `v0.5.0-rc1` tag and successful Build/Publish/Verify workflow;
4. independent E:-hosted verification of all 32 public assets;
5. safe Windows preflight and packaged W1-W4 acceptance with evidence and cleanup;
6. a new RC for any product or packaging failure;
7. stable-preparation PR, annotated `v0.5.0`, exact stable asset verification and packaged replay;
8. post-release evidence PR, milestone close, and evidence-based cleanup of every devbox worktree and
   branch.

Until those gates pass, the repository and README continue to identify v0.4.2 as the latest stable
release.
