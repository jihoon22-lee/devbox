# v0.6.0 integrated release preparation (#492/#493)

## Overview

W01~W10에서 병합한 15개 앱 기능을 한 번의 stable `v0.6.0` 배포로 묶기 위해 app version,
locked dependency, GitHub Actions runtime, unpublished Windows package checkpoint와 release
문서를 정리했다. 이 작업은 RC나 공개 release를 만들지 않는다. source PR CI, exact-main
candidate, 실제 Windows/WSL acceptance, annotated tag의 새 public package 검증을 순서대로
통과해야만 공개한다.

## Context and decisions

- 공개 Latest는 v0.5.1이며 15개 앱, 32개 public asset, 31개 manifest-declared asset 계약을
  유지한다. 2026-08-31 read-back에서 v0.5.1은 non-draft/non-prerelease Latest, digest 누락 0,
  annotated tag object `866fa9317e0abaaa84b09237fae149cbc57474db`, peeled commit
  `300cb158d1f0c23973857549a1aeddd9997c3f16`으로 확인했다.
- candidate는 release/RC/draft가 아니라 7일 보관되는 private Actions artifact다. workflow에는
  `contents: read`만 주고 release create/edit/upload 명령을 허용하지 않는다.
- package evidence와 최종 tag가 같은 source identity를 가리켜야 한다. CHANGELOG 날짜와 모든
  version metadata를 source PR에서 확정하며, candidate 이후 source나 문서를 바꾸면 기존
  candidate를 무효화하고 새 main commit에서 다시 만든다.
- 앱 version은 bundle tag와 분리한다. 모든 binary가 바뀌었으므로 각 앱의 변경 수준에 맞춘
  minor version을 사용하며 모노레포 전체를 억지로 `0.6.0`으로 맞추지 않는다.
- 자원 압박을 줄이기 위해 frontend는 workspace concurrency 1, Rust는 전용 Linux-native target과
  `CARGO_BUILD_JOBS=1`/`-j1`로 검증했다. 사용자 소유 프로세스는 종료하지 않았다.

## Changes made

### 1. Exact 15-app version contract

| App group | Version |
|---|---:|
| port-manager, developer-toolbox | 0.4.0 |
| wsl-desktop, api-playground, everything-plus, knowledge-base, life-log, devbox-manager, code-pad, run-manager | 0.5.0 |
| workbench, webhook-lab, repo-manager | 0.3.0 |
| devbox-launcher, log-lens | 0.2.0 |

변경이 필요했던 8개 앱은 `package.json`, `src-tauri/Cargo.toml`, `tauri.conf.json`을 함께
올렸다. 이미 목표 version이었던 7개 앱을 포함해 15개 모두 `Cargo.lock`과
`windows-packaged-smoke-config.json`까지 같은 값을 갖는지 fail-closed checker로 확인했다.

### 2. Dependency and notice refresh

- yanked `chacha20 0.10.1`만 compatible non-yanked `0.10.2`로 올렸다. 상위
  `lopdf 0.44.0`/`tungstenite 0.30.0`과 feature surface는 바꾸지 않았다.
- `THIRD_PARTY_NOTICES.md`를 locked graph에서 재생성했다.
- Cargo lock SHA-256은
  `ebe22c7df176d95685cc9ff9c0eb3760ac08b95829498d7c5884f89dd10977c7`, notice 파일
  SHA-256은 `6cbc242562e62ac8892bc88e3ca8fcad5e1dd7911db2b46a200cb8d1786a26d9`다.
- `glib 0.18.5` GHSA는 Tauri 2.11.5 GTK3 graph와 patched 0.20 compatibility를 재검토했다.
  Windows package가 link하지 않는 engineering boundary와 2026-11-30 expiry를 유지하되
  Dependabot alert는 dismiss하지 않는다.

### 3. GitHub Actions runtime migration

- official actions를 checkout v7, setup-node v7, cache v6, upload-artifact v7,
  download-artifact v8로 옮겼다.
- Node 22 setup 뒤 Corepack으로 root의 exact `pnpm@9.0.0`을 활성화한다. Node 20 runtime의
  `pnpm/action-setup`은 제거했다.
- 모든 workflow action reference를 allowlist로 검사한다. upstream `action.yml` read-back에서
  `dtolnay/rust-toolchain@stable`은 composite, `Swatinem/rust-cache@v2`는 Node 24,
  pinned cargo-deny action은 Docker임을 확인했다.
- release workflow의 중복 Windows package loop를 공용 strict PowerShell helper로 추출했다.

### 4. Unpublished Windows package checkpoint

- `.github/workflows/windows-package-candidate.yml`은 manual dispatch만 받고, input commit이
  checkout HEAD와 exact current `origin/main`인지 확인한다. stable tag/release가 이미 있으면
  build 전에 실패한다.
- 첫 `windows-2025` job은 15개 앱을 순차 package하고 app별 portable/NSIS를 즉시 staging한다.
  notices와 manifest를 더한 flat 32-file set은 regular-file-only이며 symlink/reparse와 추가
  entry를 거부한다.
- candidate metadata는 stable tag intent, exact commit/repository/run, 32개 size/SHA-256만
  기록하며 flat asset directory 밖에 둔다. verifier는 candidate의 strict envelope와
  15 apps/31 declared/32 downloaded/metadata asset/mismatch 0을 확인한다.
- 두 번째 fresh Windows runner는 pinned v0.5.1 32 assets를 독립 다운로드해 15개 앱 모두
  install → candidate update → uninstall → candidate fresh install → v0.5.1 rollback → final
  uninstall을 수행한다. registry/install/shortcut/app-data/integration residue가 남으면 실패한다.
- lifecycle harness는 GitHub-hosted disposable runner와 run-owned scratch에서만 mutation하며,
  pre-existing Devbox process/data/install/shortcut이 있으면 시작 전에 중단한다.

### 5. Artifact verifier hardening

- `verify-downloaded-release.py`가 public release와 unpublished candidate를 명시적으로 구분하고
  공통 결과에 `artifactKind`와 `metadataAssets`를 기록한다.
- candidate는 publication flags를 받을 수 없고 exact stable tag, null draft state, strict
  metadata key set을 요구한다. public release는 기존 draft/prerelease 검증을 유지한다.
- manifest asset 이름은 separator/control/`.`/`..`을 거부하며, downloaded symlink와 remote
  duplicate/unsafe name도 실패한다. malformed non-object asset이 traceback 대신 검증 실패로
  닫히는 회귀 fixture를 추가했다.
- packaged portable smoke는 release/candidate verification shape를 각각 exact-key로 확인한다.
- Python release-tool tests가 만드는 `__pycache__`/bytecode는 repository에서 제외해 검증
  부산물이 release source에 섞이지 않게 했다.

### 6. Release documentation

- `CHANGELOG.md`, README, roadmap, architecture와 통합 계획에 W01~W11, app versions,
  dependency/runtime 결정, candidate/physical/publication 경계를 기록했다.
- README와 architecture는 v0.6.0 tag/release가 아직 없고 v0.5.1이 공개 Latest임을 명시한다.
- 실제 실행하지 않은 Windows high-contrast, screen reader, IME, DPI와 WSL packaged 흐름은
  PASS로 표시하지 않고 #492/#493 gate에 남긴다.
