# v0.7.0 stable publication and release graph guard

## Overview

devbox v0.7.0 is the current public stable release. The exact-main Windows candidate passed all
15 packaged runtime and installer lifecycle contracts, and the annotated tag promotes the same
32 candidate files without rebuilding the applications.

The first stable promotion exposed a GitHub Actions job-graph edge case: the stable path
intentionally skips its prerelease builder, and that skipped ancestor propagated through the
successful draft-stage job to skip the final verifier. The release remained a private draft. The
complete draft was downloaded and passed the repository's exact release verifier before it was
published manually as stable Latest. This change makes that final verifier's run condition
explicit and records the completed release across current documentation.

## Publication recovery

Release workflow `33785966618` validated the immutable annotated tag, resolved the successful
candidate, verified its provenance and asset digests, and uploaded exactly 32 assets to a new
draft. The `build-prerelease-windows` job was correctly skipped for a stable tag. The downstream
draft-stage job ran under an explicit `always()` condition and succeeded, but the final job had
only GitHub's implicit `success()` condition and was skipped because of the earlier skipped
ancestor.

No unverified release was exposed. All 32 draft assets were freshly downloaded into an isolated
temporary directory and passed the same command used by the workflow's final job:

```text
artifact kind: release
tag / commit / draft / prerelease: expected
release / metadata / downloaded assets: 32 / 32 / 32
manifest apps / declared assets: 15 / 31
verified assets: 32
missing / undeclared / failures: 0 / 0 / 0
status: PASS
```

The downloaded manifest and notice hashes matched the successful candidate evidence. Only after
that check was the draft changed to `draft=false`, `prerelease=false`, Latest. GitHub's release API
then read back the same state and 32 assets.

## Release graph correction

Files:

- `.github/workflows/release.yml`
- `.github/scripts/test-release-candidate-promotion-config.py`

The final `verify` job now replaces the implicit job condition:

```yaml
if: >-
  ${{
    always() &&
    needs.preflight.result == 'success' &&
    needs.publish.result == 'success'
  }}
```

This ignores an irrelevant skipped ancestor while remaining fail-closed on both direct inputs.
The static release-promotion contract isolates the final job block and requires all three clauses,
so deleting the explicit guard fails CI.

publication-status correction does not change dependencies, lockfiles, application versions or
