## Behavior and review boundaries

The legacy Notes, Life Log and Everything+ UI trees are shared through
`packages/knowledge-features`; legacy entries keep the same feature implementations.
Knowledge lazily loads Notes/Daily, Activity and Search, retains visited drafts,
and shares civil-date selection without creating notes automatically. Notes'
static closure excludes Activity, file extractors and Mermaid, below the original
970,000 raw / 325,000 gzip ceiling. Feature CSS is scoped; the shared shell's
controls style only their intended shell elements.

Typed native adapters reuse the three original engines while fixing private
product storage and common snapshots per process. Native authorization separates
Notes writer, Activity collector, Search query/index settings, opener and migration.
Collection starts OFF; imported consent does not silently enable collection.
Close-to-tray is an explicit persisted setting; normal close otherwise exits.

Daily, Activity and session summaries use existing claim/preview/cancel/exclusive
save/ack contracts. Summary metadata is bounded and allowlisted; commands, logs,
window titles and secret values are not automatically copied. Git aggregation
preserves common repository/worktree provenance and source/range diagnostics.

Search preserves separate Notes/file FTS, full filters/settings/extractors and
nested-root ownership. Source queries return bounded generations and explicit
partial/stale/unavailable states. A 500 ms regex worker deadline permits recovery.
File/current-project work shares bounded workers and retained-handle retirement;
SQL applies the verified project prefix before LIMIT. Opening uses opaque refs
and rechecks generation, owner, source, row revision and pinned file/root/project
objects. Renderer paths, replaced objects and cancelled references are rejected.

The native Project Registry projection invalidates stale project queries and
preserves unmapped/offline/ambiguous Activity rows. Its schema-v1 fixture carries
exact B01 context and native path binding. B04/B07 own actual authenticated
publication/distro resolution; B06 owns real session-summary publication and retry
with the same descriptor. Producer/receiver fixtures are not claims that those
transports are connected.

## Data and recovery

The explicit importer snapshots WAL consistently, validates pinned v0.7 schemas
and writes three unselected destination databases. Authoritative templates,
settings, history, roots/exclusions/saved queries and reserved deleted-root IDs
are mapped; derived FTS/link indexes are rebuilt and transient deliveries are
retired. Search meta accepts only known schema/ownership/allocator keys and exact
`pdf-v1`, `docx-v1`, `xls-v1`, `xlsx-v1`, `ods-v1` markers from v0.7.
Unknown/future/corrupt input is rejected without replacing it with an empty store.

Activation requires reviewed plans, source writer quiescence and unchanged
source/destination snapshots. Repeat imports do not duplicate data or replace
new product edits. Recovery preserves both generations and refuses rollback over
newer writes. Markdown/assets remain in the user vault; executable rollback does
not undo external vault edits. Native owner leases exclude competing product
installations and active legacy writers, including spelling aliases.

A scheduled vault change keeps the live binding until restart. On next start,
preview/cancel/apply checks folder identity and ownership, keeps existing notes
and templates, and selects a new source identity. Incomplete/offline scans preserve
last-good data; filesystem work stays off startup/query admission.

The [requirement and table/file map](../docs/architecture/v0.8-knowledge.md) links
101 legacy features and seven preserved groups to implementations/tests. Older
Activity Timeline input and browser-owned settings need explicit B08 report paths;
they are not silently represented as migrated.

## Corrections established by acceptance

Search now preserves previous rows throughout full/format scans. A bounded
connection-local scan table permits pruning only after complete batches and
final native root revalidation. Retained root identity covers traversal and
extraction. Queued incremental events validate the root/parent and preserve rows
on access errors instead of treating an offline path as deletion. Regressions
cover cancellation after traversal, a moved root, queued offline events and
successful reconnect/deletion. Native WSL1 then passed the previously failing
zero-row outage query without extending query deadlines.

The Windows acceptance gate also exposed a Webhook cancellation defect. Accepted
sockets are explicitly blocking; reads/writes poll cancellation at 100 ms while
preserving the five-second request/response IO budgets and configured rule delays.
HTTP framing uses Read/Write without cloning the connection. The 82 core and seven
native regressions cover delayed first bytes/split bodies and stop without relying
on socket shutdown. The final Windows run passed authority, API Studio flows and
listener/service lifetime checks.
