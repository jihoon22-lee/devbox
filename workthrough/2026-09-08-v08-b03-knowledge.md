source-owned provider contracts and their importers in one PR. The v0.7 apps

## Extraction and ownership findings

The three frontend trees and their existing tests now live in
`packages/knowledge-features/{src/notes,src/activity,src/search}`. Legacy entry points
consume the same implementations. All 46 moved source/test/style files are
byte-identical except the Search catalog import's relative path. The Knowledge

Actual source stores take precedence over stale README wording:

|---|---|---|
| Knowledge `com.devbox.knowledgebase/data.db` | `settings`, `note_templates`; existing vault binding | `docs`, FTS, link keys and backlinks are derived; preview approvals are transient |
| Life Log `com.devbox.lifelog/data.db` | `sessions`, privacy/project/idle settings, bounded draft-history metadata | Live collector/sessionizer and operation handles are transient |
| Everything+ `com.devbox.everythingplus/data.db` | `roots`, saved query/filter definitions and root-ID allocation metadata | File/content FTS and extractor markers are derived; watcher/query state is transient |

Knowledge's `lib.rs` initializes `data.db` under `app_local_data_dir`; templates
are in that database, despite the README's vault-local wording. Markdown/assets
remain in the original vault with their bytes and relative links unchanged.
No importer may call the legacy schema initializer on the source database.
Snapshots must include committed WAL state, and writes belong to new owner stores.

Life Log's legacy tracking switch is process-local and starts true in its
standalone entry point. Its privacy rules are persistent. The new product must not infer
consent from the presence of an old DB or silently enable tracking after import.
Search root IDs are monotonic and stale saved root IDs must never name new roots.

## Consistent import, vault ownership and recovery

The native startup gate now offers source selection and an explicit import preview.
Active products schedule this review for their next launch, leaving dirty editors
mounted. Jobs run away from IPC, have a cancellation token and share one activation
reservation with new-store startup. Unknown/future metadata is preserved and blocks
unsafe initialization. Original source paths are the three native app-local profile
identifiers; the renderer cannot supply migration source paths.

SQLite online backups include committed WAL pages. An unselected generation clones
the current product databases before importing authoritative rows. The importer
keeps settings/templates, Activity sessions/privacy/history and Search roots/saved
queries; it rebuilds source FTS/link indexes asynchronously. Current last-good indexes
remain in the cloned stores. Exact table/column inventories and real domain validators
reject corrupt/future input. Table receipts prevent repeat imports from overwriting
newer edits or resurrecting destination deletions. Template collisions receive a
bounded alternate name; saved query root IDs are remapped, with tombstones for deleted
roots. Legacy collection consent and close-to-tray preference are never imported.
Pending deliveries become expired metadata with valid expiry timestamps, without
copying or replaying handoff payloads.

Durable preparation/activation/recovery phases surround one generation pointer.
Applying rechecks source and destination snapshots; rollback compares authoritative
rows, permits derived-index rebuilding, refuses newer user edits and retains both
generations. No rollback deletes/restores external Markdown or image bytes. Snapshots
are capped at 256 MiB, scans at 500,000 rows/128 MiB text/1 MiB per cell and 30 seconds;
online backup has its own ten-second deadline. Disk preflight, cancellation, eight
retained plan slots and owned cancelled-stage cleanup bound staging.

Imported vaults retain a Windows share-read-only legacy DB handle; an open old writer
prevents activation, and a new writer cannot reopen until ownership is released.
Independent product installations also contend on a shared exclusive vault lease.
Windows case/extended paths, WSL UNC aliases and `/mnt/<drive>` aliases map to the same
lease while Linux path case is retained. WSL leases require no remote filesystem
lookup. Watcher restoration and note filesystem calls run away from startup/IPC so
unavailable vaults do not block the other domains. Per-write identity checks remain
in the existing note engine. Live arbitrary vault rebinding remains blocked.
