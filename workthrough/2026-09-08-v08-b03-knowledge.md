# B03 — Knowledge, Activity and Search

Refs #541, #542 and #545. B03 combines Notes/Daily, Activity, full Search,
source-owned provider contracts and their importers in one PR. The v0.7 apps
remain available until B09; no acceptance item is complete merely from extraction.

## Extraction and ownership findings

The three frontend trees and their existing tests now live in
`packages/knowledge-features/{src/notes,src/activity,src/search}`. Legacy entry points
consume the same implementations. All 46 moved source/test/style files are
byte-identical except the Search catalog import's relative path. The Knowledge
CodeMirror test setup moves with its tests. Mechanical movement is staged separately
from later product wiring and data/authority changes.

Actual source stores take precedence over stale README wording:

| Source | Preserve | Derived / transient |
|---|---|---|
| Knowledge `com.devbox.knowledgebase/data.db` | `settings`, `note_templates`; existing vault binding | `docs`, FTS, link keys and backlinks are derived; preview approvals are transient |
| Life Log `com.devbox.lifelog/data.db` | `sessions`, privacy/project/idle settings, bounded draft-history metadata | Live collector/sessionizer and operation handles are transient |
| Everything+ `com.devbox.everythingplus/data.db` | `roots`, saved query/filter definitions and root-ID allocation metadata | File/content FTS and extractor markers are derived; watcher/query state is transient |

Knowledge's `lib.rs` initializes `data.db` under `app_local_data_dir`; templates
are in that database, despite the README's vault-local wording. Markdown/assets
remain in the original vault with their bytes and relative links unchanged.
No importer may call the legacy schema initializer on the source database.
Snapshots must include committed WAL state, and writes belong to new owner stores.

Life Log's legacy tracking switch is process-local and starts true in its
standalone entry point. Its privacy rules are persistent. The new product must not infer
consent from the presence of an old DB or silently enable tracking after import.
Search root IDs are monotonic and stale saved root IDs must never name new roots.

## Native initialization and collector consent

Notes and Search now reuse the same explicit-root initialization functions in
standalone and product component modes. Existing schema/index/watcher restoration
is preserved. An unconfigured product vault is created only under its own data
root; imported bindings must first pass the product ownership/quiesce gate.
Markdown/assets are not moved. Pending-open state is native-managed and duplicate
owner initialization fails. Notes claim/save/discard/renew and Activity history
use the supplied handoff namespace, with legacy defaults only in standalone mode.

Activity product initialization does not migrate old identifiers or absorb the
activity-timeline DB. The collector starts OFF unless an exact product consent
setting is present. Explicit start persists consent before enabling; stop disables
collection even if saving fails and reports that failure. A shared control lock
serializes observations and start/stop. Read errors and malformed/legacy settings
never imply consent. The importer must exclude the reserved product consent key.
The legacy executable retains its prior process-local startup behavior.

Product autostart derives a separate registry value from the native Knowledge
installation identifier and current executable. A foreign command in that value
is an ownership conflict; status and disable do not adopt/delete it. The legacy
LifeLog value is untouched by component adapters. Windows runtime validation of
this boundary remains pending.

All three crates now default to a standalone feature; product consumers can link
without compiling the old run/embedded UI entrypoint. Strict Clippy passes with
and without standalone code. Three consent regressions pass (file-backed restart,
failed persistence and malformed/legacy settings); the three domain suites pass
373 tests after initialization extraction in 19.850 seconds. The autostart owner-name regression also passes; final affected/Windows execution
remain pending.

The accepted B02 main (`229295f`, PR #555) is integrated without duplicating its
