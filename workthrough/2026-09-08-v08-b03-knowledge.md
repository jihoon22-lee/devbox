# B03 — Knowledge, Activity and Search

Refs #545, #541 and #542; draft PR #556. This single bundle contains the shared
feature extraction, product host, three-store importer, source API and acceptance
fixtures. B03 remains incomplete; public v0.7 apps remain unchanged until B09.

## Behavior and ownership

The 46 frontend source/test/style files moved into `packages/knowledge-features`
with only the Search catalog import adjusted. Legacy entry points consume those
same features. Typed native adapters reuse the three existing engines without
starting legacy applications. Mechanical moves and semantic changes are separate
commits. The product registry checks local window, installation, session, route,
component and replay state; UI navigation does not grant additional authority.

| Owner | Authoritative data | Derived or transient data |
|---|---|---|
| Notes | Original Markdown/assets; SQLite settings and templates | FTS, backlinks; previews |
| Activity | Sessions, privacy/project settings, bounded draft history | Collector handles and current operations |
| Search | Roots, saved queries/filters, monotonic root IDs | File/content FTS, extractor markers, watchers and query references |

A native startup gate selects three separate product databases through one
installation-specific generation pointer. New users explicitly create a private
vault; import never initializes a legacy source. Visited routes preserve drafts,
hidden dialogs respect the active route, and Notes defers Activity, Search and
Mermaid. Windows/WSL watcher restoration and note filesystem operations run away
from shared startup/IPC work. Existing per-write vault identity checks remain.

Daily and Activity share a system-local civil date. Selection creates no note.
Existing Daily notes use normal dirty confirmation; new notes require an expiring
one-time preview and exclusive publication. Cancelled/replaced/expired previews or
a racing file cannot write. An index failure preserves published Markdown.

Activity starts OFF and requires separate product consent. Normal exit flushes and
stops collection while preserving consent. Product autostart uses its own native
installation identity and refuses foreign commands. Close quits by default;
explicit close-to-tray requires an available tray and does not enable collection.
Tray Quit and Show are wired, but actual tray-menu Quit interaction is not yet
claimed as native acceptance.

Selected-day Activity digests reach Notes through the existing one-time handoff
store and a native callback. Only an opaque draft reference crosses owners.
An unread pending slot rejects replacement. Notes activates for its existing
preview/claim/renew/cancel flow; explicit save publishes and consumes once. Activity
cannot write the vault. Standalone Life Log still uses its legacy launcher.

## Git activity attribution

Calendar and digest/export now use one read-only Git collector. Git's canonical
common directory plus commit object ID deduplicates linked worktrees and path
aliases; independent repositories retain their own counts even for the same hash.
Shared commits belong to the first sorted configured path, keeping totals equal to
per-project and civil-day sums. Hashes, messages, authors, notes, signatures and
remotes never enter summaries. Fixed argv suppresses decoration/notes/signature
output; metadata and history share the existing two-second per-project budget.
No extra filesystem probe or dependency is introduced. Exact half-open millisecond
filtering and cancellation remain in the collector. Malformed project output cannot
partially modify the deduplication set. Legacy calendar Git waits move off the async
executor, and unavailable project rows remain visible instead of showing zero as a
successful count. Full Project Registry association still needs its provider.

## Import and recovery

The importer uses WAL-consistent backups of the three known legacy app-local
profiles, then writes an unselected product generation. Table receipts remap IDs,
reserve deleted root IDs and preserve destination edits/deletions on repeat import.
Template name collisions receive bounded alternate names. Real domain validators
reject unsupported templates, filters and draft histories. Legacy collection/close
consent is excluded; pending deliveries become valid expired history without replay.
Original Markdown/assets and relative links stay in place.

Preparation, cancellation, activation and recovery have durable journal phases.
Apply requires separate preview approval, unchanged source/destination snapshots
and three validated stores before switching one pointer. Rollback allows derived
index changes but refuses newer authoritative edits. Both DB generations and all
vault bytes remain. Bounds include 256 MiB per snapshot, 500,000 rows, 128 MiB text,
1 MiB per cell, 30-second scans, ten-second online backups, disk preflight and eight
retained preparation slots with ownership-checked cancelled-stage cleanup.

Imported vaults require the old Windows SQLite writer to close. A retained DB
handle prevents its reopening, and a shared exclusive vault lease prevents a second
product installation from writing. Windows/WSL aliases share a lease while Linux
case is retained. Directory handles require read access to enforce rename sharing;
WSL lease naming performs no remote filesystem lookup. Folder changes use a
reviewed next-start flow; direct live rebinding stays intentionally blocked.

## Reviewed folder changes

Notes can schedule an existing folder for next-start review while its mounted
editors and current vault remain usable. A missing native folder can also be
replaced from startup without initializing that engine. Preview inspects identity
and ownership without creating folders. Explicit apply prepares only the fixed
layout, then changes the Notes binding and native approval receipt in one SQLite
transaction with derived-index cleanup. Templates/settings, original Markdown and
assets in both vaults remain. Failed cleanup rolls the transaction back; unknown
store inventories/versions are rejected before any cache deletion.

The receipt binds the plan ID, requested target and actual canonical root. It makes
commit-before-schedule-cleanup crashes resumable and rejects substituted targets.
The note source root identity changes with the new approval. Scheduling and import
review are mutually exclusive. Remote probes precede the short local activation
gate, so a cancelled slow probe cannot hold the old store hostage or apply later.
Only one worker is admitted; jobs have five-second precommit deadlines and previews
expire after five minutes. Once configuration is committed, responses distinguish
activation/restart recovery from cancellation. A failed precommit apply may leave
explicitly approved empty layout directories; it never removes existing files.

Search references now pin the original file and root objects until retirement,
preventing filesystem ID recycling. Both search objects and folder-preview leases
use a shared bounded retirement primitive so a slow OS close never runs under an
IPC state mutex. Search pools cap active plus retiring pairs at 8,000 per source;
the separate folder-preview pool caps at two. Admission remains occupied until
close finishes. An unavailable retirement worker disables further admission and
retains only the existing finite budget until process exit.

## Search API and full surface

Notes / Current Project / All Indexed Files share the existing search surface,
including filename/content/regex, filters, roots, index status and saved searches.
Notes title/content FTS remains physically separate from file FTS. Notes supports
its title/body projection; file-only filters explicitly report unsupported there.
Current Project accepts the native B04/B07 provider contract described below; it
reports unavailable context until that authenticated transport is connected. No
renderer-supplied project path is accepted as authority.

`source_query`, `source_poll` and `source_cancel` return native query/store
generations, source/root identity, bounds, availability and partial/stale status.
Consumers cancel their own generations. Independent read-only SQLite connections
have progress cancellation and a 1.5-second deadline. Two retained worker permits
per source bound blocked OS calls; cancellation does not falsely free a permit.
Four retained jobs, 2,000 rows and a 4 MiB candidate projection bound result storage.
Notes caps at 100 and content files at 200. References expire after three minutes.
Cached watcher health preserves last-good rows and skips known-offline probes;
native roots are checked before WSL. Late replies cannot revive cancelled rows.

The UI shows source/root and stale/unchecked status, applies only the newest query,
and forwards the selected row's exact opaque reference. Unchecked rows remain
inspectable/copyable but cannot open. The separate opener rechecks store generation,
registered row/deepest root, vault/root and file object identity immediately before
opening. Its two permits remain held through blocked probes, responses have a
two-second deadline, and expired work cannot launch later. Notes results return to
the existing editor/dirty confirmation. Raw renderer paths and old raw query methods
are rejected by the product; standalone command behavior is preserved.

Product regex preserves JavaScript syntax but evaluates filenames in a dedicated
worker terminated after 500 ms or cancellation. This bounds catastrophic
backtracking without freezing the editor. No dependency was added.
