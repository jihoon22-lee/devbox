# B03 — Knowledge, Activity and Search

Refs #541, #542 and #545. B03 combines Notes/Daily, Activity, full Search,
source-owned provider contracts and their importers in one PR. The v0.7 apps
remain available until B09; no acceptance item is complete merely from extraction.

## Extraction and ownership findings

The three frontend trees and their existing tests now live in
`packages/knowledge-features/{src/notes,src/activity,src/search}`. Legacy entry points
consume the same implementations. All 46 moved source/test/style files are
byte-identical except the Search catalog import's relative path. The Knowledge
CodeMirror test setup moves with its tests. Mechanical movement is staged separately
from later product wiring and data/authority changes.

Actual source stores take precedence over stale README wording:

| Source | Preserve | Derived / transient |
|---|---|---|
| Knowledge `com.devbox.knowledgebase/data.db` | `settings`, `note_templates`; existing vault binding | `docs`, FTS, link keys and backlinks are derived; preview approvals are transient |
| Life Log `com.devbox.lifelog/data.db` | `sessions`, privacy/project/idle settings, bounded draft-history metadata | Live collector/sessionizer and operation handles are transient |
| Everything+ `com.devbox.everythingplus/data.db` | `roots`, saved query/filter definitions and root-ID allocation metadata | File/content FTS and extractor markers are derived; watcher/query state is transient |

Knowledge's `lib.rs` initializes `data.db` under `app_local_data_dir`; templates
are in that database, despite the README's vault-local wording. Markdown/assets
remain in the original vault with their bytes and relative links unchanged.
No importer may call the legacy schema initializer on the source database.
Snapshots must include committed WAL state, and writes belong to new owner stores.

Life Log's current tracking switch is process-local and starts true in the legacy
entry point. Its privacy rules are persistent. The new product must not infer
consent from the presence of an old DB or silently enable tracking after import.
Search root IDs are monotonic and stale saved root IDs must never name new roots.

## Actual verification and remaining work

Shared feature TypeScript build and all 179 moved UI tests (19 files) pass with
two workers. The product metadata checker passes with all parity statuses pending.
The catalog-relative import was corrected after the first build identified its
old location. No Windows or native product behavior is inferred from these tests.

All 84 registered native commands now have typed internal adapters with the existing
camelCase request shape, unknown-field rejection and JSON null for void results.
They add no Tauri command exposure, product initialization or legacy launch path.
Knowledge/Activity/Search states can select a native-owned snapshot root; legacy
constructors retain their existing default. Activity export/digest/source discovery
use that root without falling back to another installation. Saved-query publication
retains its rollback contract. Strict Clippy passes and 370 native regressions pass,
including explicit snapshot namespace separation. Product activation is not wired
yet and these results do not complete B03 acceptance.

All three legacy frontend builds pass after extraction. Their entry points retain
the required shared CSS imports and a standalone axe smoke test each; all three
smokes and the 19-app accessibility contract pass. These small entry tests preserve
the app-level verification gate while the full behavioral tests run in the feature
package. Final affected validation follows.

The first affected attempt stopped in its scope regression, before compilation:
the expected editor consumers still described the old frontend layout. The
catalog's direct import now belongs to the shared feature package, so its virtual
edge uses workspace directory identities and includes all reverse consumers.
The scope regression verifies both app and shared-package catalog imports and
passes with the expanded editor/catalog/feature consumer sets.

portable Rust tests, 179 shared feature UI tests, the three standalone entry

memory peaks at 6,445,027,328 bytes within the unchanged 8 GiB maximum. The three

budgets. Windows compilation/execution of this revision remains pending.
