# B02 API Studio consolidation

Tracking: #544, master #541, acceptance #542. Implementation in progress; no
Windows product parity or migration completion claimed yet.

## Changes

- Extracted API Playground's six pure protocol modules into `crates/api-protocols`.
  Legacy API commands and the new API Studio API component share the same engine.
- Moved the three frontend implementations and their 623 tests into
  `packages/api-studio-features`. Legacy entry points consume the same exports.
  API Studio lazily opens Requests/Protocols, Webhooks and Transforms; mounted
  feature groups retain their drafts and native connections across navigation.
- Added explicitly enumerated native adapters around the existing commands.
  New product startup initializes state without running legacy bootstrap or
  starting requests/listeners/processes. Storage roots use the product namespace
  and component subdirectories. Cross-app launch commands are not yet exposed.
- Legacy crates default to their `standalone` executable feature; API Studio
  disables it and links only the native component implementation. This keeps
  legacy frontend bundles and bootstraps out of the product build. The original
  standalone apps keep their existing default behavior.
- Product IPC checks the native main window, registered component owner, session,
  installation, context, replay, admission deadline and bounded arguments before
  dispatch. Active IDs stay reserved across long awaits. Responses carry native
  operation provenance; dialogs and explicit clipboard reads use that boundary.
- Catalog revision 2 declares only API Studio's three additional authorities.
  Public v0.7 selection remains 15 apps. Historical source paths are retained
  alongside relocated inventory paths.
