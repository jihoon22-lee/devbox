existing engines and frontend implementations. Legacy standalone applications
remain available under the public v0.7 catalog until B09. Core extraction is in
`805986a` and `5cb48e2`; frontend relocation and native wiring begin in `1710576`.
Later commits isolate standalone assets, implement workflows/importers and fix
regressions. The feature inventory retains baseline paths alongside current paths.

- `crates/api-protocols`, `webhook-core`, `transforms-core` and `data-migration`
  have actual legacy/product consumers. `packages/api-studio-features` contains
  the shared UI and its original tests. Legacy entry points retain CSS and axe
  smokes. Component dependencies disable their `standalone` feature so the product
  embeds only its own frontend and does not invoke a legacy bootstrap.
- Requests, Webhooks and Transforms load separately. Mounted groups retain drafts
  and protocol sessions; navigation does not restart a listener or connection.
  History/Console separates persisted HTTP/gRPC summaries from live sessions.
- API Workspace stores bounded Collection/environment/OpenAPI/Mock-profile ID sets.
  Selection filters lists without replacing the current request/environment or
  network session. Revisions, OS locks and atomic writes reject stale edits.
  Project association requires native-verified context; WP07 supplies the provider.
- Explicit OpenAPI saves retain supported request/Mock projections, not the original
  schema archive. The native request codec preserves duplicate header order/enabled
  values and exact secret references while masking literal/disabled credentials.
  Reopening previews a draft; delete/apply/send/listener startup stay separate.
- Internal capture→Requests, selected response→Transforms/diff, eligible result→
  Requests, and response/transform/OpenAPI→Mock use typed one-time previews with
  explicit apply. Mock apply replaces only the editor draft. Native pending state,
  peek/ack navigation, leases and busy-receiver rollback prevent lost or duplicate
  delivery. Diff inputs survive tool navigation. Replacement hunks include both
  delete and insert so the new column remains visible.
- A fixed 21-tool manifest preserves individual export/pipeline policy. HMAC is
  excluded from persistence and handoff. JWT/response outputs use native redaction.
  Requests/Transforms can explicitly keep a masked owner-private Knowledge draft;
  History/Console can reopen/export/delete it. Missing receivers are reported
  accurately and the saved draft survives restart.

## Authority, ownership and lifetime

The product uses `com.devbox.v08.apistudio` plus the native executable installation
identity, with separate component storage and `handoff/v1` namespaces. Native
admission validates main window/local origin, registered component, session,
installation, context, request bounds, replay and admission deadline. Active IDs
remain reserved over long awaits. UI routes and renderer metadata do not grant
another owner access. Responses carry native operation provenance. Window getters
run before the session mutex is acquired to avoid a UI-thread/session-lock deadlock.
This is logical authority separation, not a claim of a same-user OS sandbox.

The temporary Webhook listener defaults to stop-and-quit. Explicit tray hiding
keeps it running; full quit stops it. Service exports are disabled drafts with no
autostart/restart. Explicit `--service-profile` processes use the existing bounded
listener directly, with no Tauri App, event loop, window, WebView or protocol
bootstrap. Process ownership, stop/drop cleanup and duplicate-port refusal are
independent of the UI listener. API and Runtime secrets are not merged.

## Source migration and recovery

| Source | Destination / preservation |
|---|---|
| API browser Collection/history/environment/gRPC keys | API-owned browser stores with existing sanitizer, qualified ID mappings and receipts |
| Sealed API environment/OAuth/TLS state | Existing API owner/DPAPI binding; unavailable secrets explicitly require reconnect |
| Webhook fixtures and selected service profile | Product Webhook namespace; supported conflicts preserve records; no listener startup |
| Toolbox workflow metadata | Product Transforms namespace; preferences/favorites/workflows only |
| Protocol sessions, capture/raw-header vaults, HMAC inputs/results | Remain transient and are excluded from migration |

The explicit startup gate runs before feature use. API Playground must be closed:
read-only exclusive LevelDB handles protect a consistent file set, identities are
checked, and only that store is copied. A suspended child joins the existing owned
process Job before running an isolated exporter. COM verifies its actual WebView2
profile; the exporter cannot invoke product commands or read the original profile.
WAL-consistent SQLite backup/recovery remains covered by the shared migration
harness; a live `.db` copy is never used as its replacement.

Raw copies/tickets are removed after export, including failure paths. Scratch
cleanup bounds enumeration, checks root identity and ancestors, and treats child
links as leaves under the standard library's
[non-following removal contract](https://doc.rust-lang.org/std/fs/fn.remove_dir_all.html).
An enumerated child that has disappeared is already absent; transient metadata,
directory and deletion failures retry within two seconds. Root metadata failures
are not treated as absence. Source acquisition still rejects links and never
changes source permissions. Superseding previews remove old staging; accepted
activation remains protected by its journal.

SQLite records intent and receipts; native-file CAS, browser read-back and final
acknowledgement complete activation. Startup blocks ordinary writes until this
sequence completes. Restart can resume or restore recorded prior values, and
unexpected third-party edits stop restoration. Completed receipts prevent duplicate
imports and preserve later product edits. This is recoverable orchestration across
stores, not one OS transaction. Completed imports cannot be automatically reversed;
new v0.8 user data is not promised to round-trip into v0.7.
