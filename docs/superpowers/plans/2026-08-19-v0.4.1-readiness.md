# v0.4.1 Release Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Close the code-verifiable gaps between the v0.4.1 terminal/app-link specifications and the implementation, align release documentation and versions, and leave only explicitly Windows-runtime verification before release.

**Architecture:** Keep `crates/applink` as the wire format and `crates/launch` as the process-launch boundary. Send targets that each receiving app can actually route today, consume the backend pending-open slot as the single source of truth for both cold and warm starts, and pass Windows build information from a small Tauri command into xterm construction. Preserve v0.5.0-only profile/layout semantics as deferred work instead of simulating them in v0.4.1.

**Tech Stack:** Rust, Tauri 2, React 19, TypeScript, Vitest, Cargo, pnpm 9, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-17-app-interop-design.md`, `docs/superpowers/specs/2026-08-17-wsl-desktop-terminal-design.md`, GitHub issue #176.
