# v0.4.2 Security Hotfix Release Plan

> **Execution rule:** 각 코드·문서 변경은 기능 단위 PR로 분리하고 required GitHub
> Actions가 통과한 뒤에만 merge한다. Windows packaged-runtime 관찰은 코드·CI 증거와
> 구분하며, 기존 사용자 프로세스와 데이터를 보호할 수 없으면 성공으로 간주하지 않는다.

**Goal:** API Playground 0.3.2의 backend-only secret resolve와 persistence/redaction
경계를 공식 Windows package에서 검증하고, 증거가 통과한 동일 source tree를 v0.4.2
안정판으로 게시한다.

**Source:** PR #225, PR #226, PR #228, PR #229,
`docs/superpowers/specs/2026-08-22-v0.5.0-native-first-plan.md` P1-02·H1,
GitHub issue #176.

**Release sequence:** `v0.4.2-rc1` release preparation → annotated RC tag → official
27-asset publication/manifest verification → isolated Windows H1 → stable preparation
PR → annotated `v0.4.2` tag → stable publication/manifest verification → issue evidence
and cleanup.

## Global Safety Constraints

- RC1과 stable tag는 각각 그 release-preparation PR이 merge된 `origin/main`의 정확한
  commit에 annotated tag로 만든다. 기존 tag나 release를 수정·삭제하지 않는다.
- API Playground의 기존 `%LOCALAPPDATA%\\com.devbox.apiplayground` 경로는 테스트 전 같은
  volume의 고유 backup 이름으로 atomic rename하고, test process와 WebView child가 모두
  종료된 뒤 생성 데이터만 제거하고 원본을 복원한다. API Playground는 현재 integration
  snapshot producer가 아니므로 존재하지 않는 integration 경로를 임의로 만들지 않는다.
- 기존 API Playground process가 실행 중이거나 파일 lock 때문에 안전한 격리가 불가능하면
  종료·이동을 강행하지 않고 H1을 미검증으로 중단한다.
- secret fixture 원문은 임의의 일회성 값으로 만들고 issue, log, screenshot, shell output에
  출력하지 않는다. evidence에는 fixture ID와 SHA-256 fingerprint의 앞 12자리만 기록한다.
- LevelDB 삭제는 물리적 byte overwrite를 보장하지 않으므로 H1의 localStorage 판정은 CDP가
  반환한 **logical key/value**를 기준으로 한다. 테스트가 의도적으로 seed한 raw v1 byte가
  LevelDB log segment에 남지 않는다고 과장하지 않는다.
- clipboard reveal을 검증할 경우 원래 clipboard를 메모리에 보존하고 `finally` 정리에서
  그대로 복구한다. clipboard 읽기·복구가 불가능하면 reveal-copy 관찰은 중단하고 masked
  cURL과 persistence 부재만 검증한다.
- H1 실패 시 stable release로 진행하지 않는다. 원인 수정은 별도 기능 PR과 새 RC tag로
  처리하며 기존 RC release를 덮어쓰지 않는다.

## Task 4 — Execute the packaged H1 matrix

### H1-A. DPAPI and backend-only resolution

- [ ] UI를 통해 secret environment variable을 추가한다. logical `apip-environments` 값은
  `secret=true`, 원문과 `plain:` prefix 부재, 비어 있지 않은 sealed envelope여야 한다.
- [ ] `${NAME}` 또는 `{{NAME}}` reference를 URL/header/body/auth에 넣어 loopback echo로
  전송하고 server가 expected secret fingerprint를 수신했음을 확인한다. DOM에 표시된 request,
  response, error, History와 logical localStorage에는 원문이 없어야 한다.
- [ ] browser-only command fallback은 packaged WebView의 runtime 경로가 아니므로 H1 성공으로
  가장하지 않는다. PR #225의 frontend 회귀 테스트에서 secret seal/send/reveal 거부와
  pseudo-sealed value 부재가 통과했음을 별도 코드 증거로 연결한다.

### H1-B. History v1 fail-closed deletion

- [ ] CDP로 raw `apip-history` v1에 direct secret fixture를 seed하고 v2·marker는 제거한 뒤
  reload한다. reload 전 fixture raw key가 존재했음을 key name과 fingerprint로만 기록한다.
- [ ] reload 후 UI가 raw history를 렌더링·검색·재전송하지 않으며 `apip-history`가 logical
  storage에서 사라졌는지 확인한다.
- [ ] `apip-history-v2`가 schema version 2의 안전한 store이고 원문이 없으며,
  `apip-history-v1-migrated=2`는 raw key 부재 확인 뒤에만 존재하는지 확인한다.
- [ ] test harness의 storage fault fixture로 v2 write, raw delete, marker write 실패 각각에서
  raw UI 격리와 marker 부재·재시도 동작을 확인한다. packaged app storage를 고의로
  손상시키거나 raw backup key를 만들지 않는다.

### H1-C. Collection safe conversion

- [ ] `apip-collections` v1에 reference field와 direct Authorization/Cookie/API-key/auth/body
  secret을 함께 seed하고 v2·marker를 제거한 뒤 reload한다.
- [ ] reference는 보존되고 direct credential은 `[REDACTED]`, auth-safe replacement 또는
  `requiresSecretReview=true`로 변환됐는지 확인한다.
- [ ] `apip-collections-v2` write/read-back 뒤 raw v1이 제거되고 marker가 기록됐으며,
  logical localStorage의 어떤 key/value에도 fixture 원문이나 raw backup/quarantine이 없는지
  전체 key scan으로 확인한다.

### H1-D. cURL, response, error, and redirect

- [ ] default cURL view/copy가 Authorization, Cookie, API key, query/body/auth direct value를
  마스킹하고 environment reference는 template 형태로 보존하는지 확인한다.
- [ ] 사용자 확인 뒤 revealed cURL이 한 번 clipboard에 생성되더라도 React state, History,
  Collection, localStorage에는 저장되지 않는지 확인하고 원래 clipboard를 복구한다.
- [ ] origin server가 cross-origin destination으로 redirect할 때 destination이 Authorization,
  Cookie, API key header, auth와 body를 받지 않았음을 boolean capture로 확인한다. 307과 308
  각각에서 method는 유지되지만 body와 stale `Content-*` metadata가 억제되는지 확인한다.
- [ ] 민감한 query 또는 fixture secret이 destination URL에 포함된 cross-origin redirect는
  destination listener에 연결하기 전에 고정된 안전 오류로 차단되는지 확인한다.
- [ ] response의 민감 header, nested JSON sensitive key, query/final URL/Location과 secret exact
  value가 DOM 및 response wire에서 `[REDACTED]`인지 확인한다.
- [ ] connection refused와 timeout 두 실패에서 UI error가 generic message이고 URL, token,
  transport 내부 오류 원문을 포함하지 않는지 확인한다.
- [ ] 성공·redirect·connection refused·timeout 뒤 logical localStorage 전체를 scan해 fixture
  원문 부재를 다시 확인한다.

## Completion Criteria

- API Playground version은 Cargo/Tauri/package 모두 0.3.2다.
- RC1과 stable release가 각각 immutable tag와 검증된 27 assets를 가진다.
- packaged Windows H1-A~D가 직접 관찰되고 logical localStorage에 fixture 평문이 없다.
- 기존 사용자 data/process/clipboard가 원상복구되고 test residue가 없다.
- v0.4.2는 Latest stable이며 P1-02 회귀 기준과 issue #176 evidence가 남아 있다.
- task-owned worktree와 local/remote branch가 모두 정리됐다.
