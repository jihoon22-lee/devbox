# v0.8.0 product consolidation

GitHub #542 owns acceptance; this versioned copy records the implementation contract.
Changes to requirements must update both references in the same bundle.

상위 계획: #541 · 마일스톤: [v0.8.0](https://github.com/jihoon22-lee/devbox/milestone/3)

## 문서 역할

이 이슈는 **무엇이 충족되어야 v0.8.0을 완료할 수 있는지**를 정의한다. WP01~09는 이를 구현하는 방법이고 B01~09는 PR 검토 묶음이다. 이슈↔PR은 N:M 관계를 허용한다. 본 명세는 한 구현 PR에서 자동 종료하지 않으며, 최종 수용 증거가 모였을 때 닫는다.

아래 MUST는 v0.8 release blocker다. 기본 구현안을 바꿀 수는 있지만 검증 기준을 묵시적으로 낮추거나 기능을 누락할 수 없다. 구현상 대안이 필요하면 본 이슈에 결정·이유·검증 방법을 기록하고 #541의 계획 매핑도 갱신한다. 계획 등록 시점의 모든 구현·실기 검증 결과는 미실행이다.

- Workspace: Overview, Source(worktree/Git), Files(editor/diff/LSP), Tasks & Services(cron 포함), Runtime(process/endpoint/health 및 WSL/container 상태·기존 action), Logs, Terminal, Problems, Dependencies.

## B. 개발 작업 문맥

### R05 — Project/Worktree/Target identity

ProjectId, WorktreeId, Windows/WSL target, distro와 path identity를 분리한다. 같은 repo의 여러 worktree, 다른 distro의 같은 path, WSL UNC alias, Windows case-insensitive와 WSL case-sensitive 특성을 오인하지 않는다. unavailable/offline/moved root를 새 프로젝트로 몰래 중복 등록하지 않는다. stale revision의 destructive command는 재확인을 요구한다.

수용: Windows 및 WSL repo, 공백/한글 경로, aliases, repo 이동, worktree 삭제/재생성, stopped/missing distro, root 밖 symlink/reparse를 검증한다. 문자열 path 비교만으로 identity를 승인하지 않는다. 담당 WP01/04.

### R06 — repository manifest + local overlay + trust

`.devbox/project.json`에는 schema version, 상대 source, expected ports, toolchain/task/session 정의 등 공유 가능한 비밀 아닌 설정만 둔다. 절대 경로, secret 값, DPAPI blob, 개인 창 상태는 넣지 않는다. local overlay는 target binding, SecretRef, 개인 layout 등을 소유한다. 가져오기/변경 diff를 표시하며 자동 실행·자동 패키지 설치·자동 커밋하지 않는다.

신뢰는 root/worktree+관련 manifest/task source revision에 연결한다. 다른 checkout/수정된 실행 정의는 재검토한다. 문서의 실행 명령이나 저장소 파일 내용 자체를 사용자 승인으로 간주하지 않는다. 담당 WP04.

### R07 — Worktree-aware Development Session

preflight → editor/terminal restore → 선택한 tasks/services 시작 → readiness/ports/logs/problems 연결을 제공한다. 복원 가능한 UI 상태와 실행 부작용을 분리한다. 부분 실패 시 각 단계·생성한 자원·정리 결과를 보여 준다. session이 발견만 한 external service, 공유해서 사용 중인 service, 기존 tmux/zellij session을 종료하지 않는다. 소유와 참조를 분리하고 operation/session ID로 중복 start를 방지한다.

수용: 두 worktree/세션 동시 실행, 중복 요청, task 시작 중 취소, 외부 service 재사용, shell 종료/전체 앱 종료/restart, 실패 cleanup. 담당 WP05/06.

### R08 — Files/Git/Dependencies/WSL LSP v1

Git 변경과 파일 저장·rename의 기존 안전성을 보존한다. UI에서 Windows/WSL execution target을 확인할 수 있다. WSL LSP는 selected distro의 설치된 검증 executable+structured argv를 사용하고 stdio framing/size/timeout/restart를 제한한다. server path URI와 client path mapping, UTF-16 range/document version, workspace edit preview/저장 충돌을 검증한다.

**새 WSL LSP의 자동 패키지 installer는 비범위이며, 기존 Windows LSP의 명시적 설치·검증 cache·local archive import 기능은 보존한다.** 두 범위를 혼동하여 기존 기능을 삭제하지 않는다.

rust-analyzer/TypeScript/Python/web-language 경로를 실제 baseline/tool availability에 맞게 adapter로 등록한다. 설치 안 됨/지원 안 됨/offline를 성공으로 표시하지 않는다. file watching과 LSP 실패가 편집기 기본 read/write를 막지 않는다. 담당 WP04.

### R09 — Runtime topology와 Unified Problems

Task/Service→Operation→Run→ProcessIdentity/Endpoint/Health/LogSource 관계를 보존한다. declared/expected/verified 정보를 구분한다. 동일 port/PID 숫자만으로 ownership을 주장하지 않으며 Windows/WSL/container별 identity 검증을 보존한다. Problem은 source, revision, project/worktree, file/range 또는 run/log ref, severity, timestamp, stale 상태를 가진다. 재실행 후 오래된 진단이 새 문제로 남지 않게 한다.

수용: task→listener→log→problem→file/run 이동, PID 재사용, 종료된 run, log rotation, 부분 source 실패, 프로젝트 전환 중 늦은 응답. 담당 WP05/06.

### R10 — Terminal 수명과 사용성

현행 tabs/panes/layout, exact/progressive restore, cwd integration, tmux/zellij 재탐색·재연결, IME, 입력/broadcast 확인, Quick Summon 계약을 보존한다. Workspace Terminal route와 보조 창이 동일 context를 사용한다. hide는 quit가 아니며 unmount가 PTY 종료를 뜻하지 않는다. live PTY/buffer는 persistence 데이터로 오인하지 않는다. arbitrary drag/dock framework는 필수가 아니다. 담당 WP06.

## D. 보안·IPC·데이터 소유

### R17 — 명시적 authority와 IPC

논리적 책임별 authority matrix를 두고 Tauri window/webview/app command 노출을 명시한다. Runtime은 owned process와 실행 시 필요한 secret만, Process Action은 선택한 외부 process 종료만 책임진다. UI 공용 shell에 모든 arbitrary backend command를 풀지 않는다.

IPC는 request ID, version, caller/session/installation identity, size limits, deadline/cancel, response provenance, replay 대응을 갖춘다. local IPC는 현재 사용자와 의도한 component에 제한하고 가능한 transport peer 검증을 적용한다. 인증용 token을 argv/history/log에 넣지 않는다. 임의 localhost port라고 안전하다고 가정하지 않는다. 같은 OS 사용자 수준 프로세스 분리는 완전 sandbox가 아님을 명시한다.

수용: 권한 없는 window/caller, 임의 renderer payload, 잘못된 component path/version/session, stale identity, replay/중복 요청/oversize/timeout 검증. destructive command의 UI 우회 호출도 거부. 담당 WP01/05/07/08.

### R18 — Source-owned ArtifactRef와 SecretRef

shared registry에는 opaque ID와 최소 metadata를 저장한다. body/로그/노트 원문, credential, 환경변수 값, 임의 command 전체를 route/recent/log/support bundle에 저장하지 않는다. Artifact는 content type, owner, revision, sensitivity/redaction, expiry/bounds, claim/ack/restore를 지원한다. large payload는 limit 안내하고 몰래 truncation하여 같은 원문이라고 표시하지 않는다.

기존 SecretReference/Sealer/AppLink를 재사용하며 중복 protocol을 만들지 않는다. **모든 결과가 exportable인 것은 아니다.** Toolbox HMAC 등의 비영속·handoff 금지, protocol session transient, Webhook raw-header memory-only 정책을 공용 Artifact가 우회하지 않는다.

Secret은 필요한 owner가 실행 시에만 해제한다. form의 사용자가 입력한 값과 저장된 secret을 일괄 복호화하여 renderer로 보내는 행위를 구분한다. API와 Runtime store를 중앙 평문 store로 합치지 않는다. support export의 민감정보는 기본 제외한다. 담당 WP01/02/05/07/08.

### R19 — component ownership와 lifecycle

각 store의 single writer, component의 product owner, start/idle/exit/restart/backoff/update behavior를 정의한다. 별도 executable 수는 고정하지 않는다. read-only Search/Activity role에 product mutation command를 제공하지 않는다. 필요한 설치/관리 작업 외에 불필요한 admin elevation을 요구하지 않는다. 임의 외부 바이너리를 component로 등록·실행하지 않는다.

네 제품 중 일부만 portable로 실행해도 나머지 제품이 설치되어 있다고 가정하지 않는다. 설치된 suite/여러 portable가 동일 이름 pipe/global shortcut/shared DB를 중복 소유하지 않게 namespace/registration/version handshake/owner lease를 정한다. 담당 WP01/03/05/06/08.

## E. 데이터 이전·업데이트·복구

### R20 — baseline와 consistent migration snapshot

지원 기준은 v0.7.0 전체/부분 설치 및 알려진 그 앱 schema다. 이전 버전/미래 schema/손상된 데이터는 명시적 진단을 제공하고 빈 store로 조용히 대체하지 않는다. source DB/config를 in-place upgrade하지 않는다. snapshot 시 WAL과 concurrent writer를 고려한 backup을 사용하고, 필요한 source quiesce와 backup artifact 검증을 수행한다.

'원본 불변'은 migration이 원본 논리 데이터/schema를 수정하지 않는다는 뜻이다. SQLite 자체 lock/SHM 행위와 writer의 정상 변경까지 byte 불변이라고 주장하지 않는다. live DB를 immutable 모드로 억지로 읽어 WAL을 무시하지 않는다. 현재 Data Inspector의 checkpoint-only 진단 reader를 consistent migration backup으로 대체 사용하지 않는다. consistent backup의 digest, schema, record counts, references, acquisition metadata를 검증한다.

### R21 — idempotency·conflicts·secrets·vault

migration journal에 source snapshot identity/revision→destination IDs를 기록하고 재실행 시 duplicate를 만들지 않는다. 동일 이름이지만 내용 다른 API collection/project/task, 기존 v0.8 destination, 부분 import 충돌에는 skip/keep-both/explicit merge 정책과 preview를 제공한다. ID mapping 후 관계를 검사한다.

**table/파일 단위로 authoritative / derived / transient를 분류한다.** Knowledge templates와 Everything+ roots/exclusions/saved queries처럼 색인 DB 안의 사용자 원본은 이전한다. 순수 FTS/link index/cache만 재생성하고 DB 전체를 캐시로 취급해 버리지 않는다. WebView localStorage와 JSON 설정의 별도 이전 경로·제약도 report한다. 자동 이전 불가 항목을 성공으로 숨기지 않는다.

vault는 사용자의 기존 경로에 남는다. transient ring/active PTY는 이전 대상이 아니며 필요한 세션은 명시적으로 재연결한다. 원본 task/job/service 정의는 보존하되 migration이 자동 start/cron firing을 촉발하지 않게 enable-state와 old/new scheduler 전환을 검토한다. DPAPI 이식 가능성은 actual entropy/user binding을 검사하고 reconnect required와 migrated를 구분한다. 평문 중간 파일 금지.

### R22 — activation·rollback의 정확한 보장

stage/backup/import/verify/quiesce/activate/health/commit/recover 상태마다 crash injection을 수행한다. activation commit 전 일반 사용자 write를 막는다. 기존 generation과 이전 데이터 snapshot을 보존한다. health 실패 시 실행 파일만 과거로 되돌리고 새 schema를 그대로 열게 하지 않는다.

activation commit 전 rollback과 이후 downgrade를 구분한다. commit 후 새 사용자 데이터를 v0.7로 무손실 역변환한다고 약속하지 않는다. downgrade 전 보존·export·영향 안내를 하고 자동으로 새 데이터를 덮어쓰지 않는다. user vault 편집은 실행 파일 rollback 대상이 아니다.

### R23 — 설치·업데이트·제거 계약

suite version lockstep + versioned component/schema handshake. metadata/digest 검증 뒤 설치하며 지원하지 않는 mixed version은 실행을 차단하고 복구 경로를 제공한다. 네 제품 portable는 필요한 component를 포함하고 공유 source를 탐색할 때 검증된 registration만 사용한다.

identifier/installer GUID/ARP/single-instance/protocol/shortcut/file association은 각각 구별하여 이전한다. anchor identifier 재사용은 검증 후 결정한다. legacy 제거는 identity가 확인된 설치/Manager-owned portable에 한정한다. arbitrary disk scan delete 금지. uninstall은 기본 user data 보존이며 data 삭제는 별도 review다. 일곱 공개 asset은 기본 배포 설계이며 실제 signed metadata 등을 반영한 최종 manifest가 검증 원장이다.

담당: R20은 WP01/02~06/08, R21은 각 owner 및 WP07/08, R22/23은 WP01 위험조사+WP08/09.

## F. 품질·개발 효율·릴리스

### R24 — 성능/회귀

WP01은 anchor cold/hot start, 첫 입력 가능 시점, idle CPU/RSS/agent 수, 대표 검색/작업/복원, route initial bundle을 같은 machine/fixture 조건으로 측정한다. 허용 예산을 구현 전에 기록하고 budget을 늘릴 때 측정·사유를 첨부한다. 초기 번들에 모든 기능을 static import하지 않는다. queue/concurrency/ring/buffer/retention은 bounded여야 한다. 수치가 없으면 '성능 개선'이나 PASS로 기록하지 않는다.

### R25 — DX/CI/리뷰

Feature metadata로 owner/route/authority/data/migration/test를 검사한다. 최소 scaffolder·route dev mode·native mock 표시·Rust/TS shared fixture를 제공한다. 실제 두 소비자가 없는 범용 프레임워크를 미리 늘리지 않는다. protected required check 이름/의미를 유지하거나 명시적으로 이전하고 root/미분류 변경은 full CI로 검사한다. 기계적 이동과 semantic 변경을 commit/리뷰 packet에서 구분한다. 9개 통합 PR budget을 기준으로 이슈 N↔PR M을 운용한다. 메인/명세/결과 기록만을 위한 별도 PR을 의무화하지 않는다.

### R26 — 공개 전환

기존 release entry/source shell/workspace member/shortcut/old executable dependency를 제거한다. shared engine/migration reader/유효한 alias는 유지할 수 있다. 삭제된 exe의 절대 경로를 호출하는 외부 script까지 자동 호환된다고 보장하지 않으며 suite-owned 등록만 검증된 방식으로 전환한다. parity inventory의 모든 필수 항목에 증거를 연결한다. exact-main private candidate의 runtime·installer·migration 검증을 마친 파일을 그대로 stable 승격한다. code change가 생기면 old candidate의 PASS를 재사용하지 않는다. 공개 RC는 사용자 명시 요청 없이는 만들지 않는다.

## 최종 시나리오 및 검증 층

| 시나리오 | 필수 확인 |
|---|---|
| S01 Windows/WSL project→worktree→edit/LSP→Git | context/identity/dirty save/target-aware commands |
| S02 session→task→port→log→problem→file→stop | ownership/partial failure/취소/외부 프로세스 보존 |
| S03 webhook→request→response diff/transform→mock→note | redaction/preview/no auto network side effect |
| S04 Activity→Daily→project note/search | 날짜/source attribution/vault 무손상/선택적 삽입 |
| S05 Launcher→전 제품/단일 portable | cold/hot/shortcut collision/없는 제품/다중 설치 namespace |
| S06 v0.7 full/partial/mixed→v0.8 | WAL/backup/conflict/secrets/중단·재개/no duplicate |
| S07 failed activation/recovery/downgrade/uninstall | 구 설치 보존/새 데이터 보존/unknown path 미삭제 |
| S08 keyboard/IME/DPI/monitor/distro offline | degraded UX/기본 작업 지속/정확한 diagnostics |

테스트는 pure fixture → Rust/TS contract → product integration → 실제 Windows/WSL → packaged candidate → public asset read-back 층으로 구분한다. mock PASS를 native PASS로 대체하지 않는다. 아직 미실행인 항목은 미실행으로 남긴다.
