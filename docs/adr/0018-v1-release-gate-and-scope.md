# 0018 1.0.0 공개 기준과 그 뒤의 범위·과정

상태: 채택 · 기록일: 2026-11-25

맥락: 1.0.0 공개는 2026-11-05부터 "Windows 확인 뒤"로 보류였다. 2026-11-25에 후보 `cc704e6f`(rc.3)로 accept 설치 스모크와 실제 claude·codex 행을 다시 돌렸다(수용 실행 `cc704e6f-a17b22a5` 8/8 PASS, `cc704e6f-282b323d`). 같은 날 전체 검토에서 다음이 드러났다. 공개 게이트 26행 가운데 대부분이 NOT_RUN으로 남아 있었고, 판정은 "버전 되돌림 PR의 SHA" 결과만 인정했다. 수용 harness(약 1.3만 줄)는 저장소 밖(Git common-dir)에만 있어 버전 관리되지 않았다. 제품 코드의 약 23%가 사용 빈도 최하위(D3의 F·G)에 쓰였다. 자체 업데이터는 공개 버전 사이에서 실행된 적이 없다. 사용자는 2026-11-25에 아래 다섯 결정을 승인했다("권장대로 모두 다 작업 후 정식 v1.0.0 버전 출시").

결정:

1. **후보 근거 인정.** 버전 문자열과 문서·시험·harness만 바꾸는 PR은 직전 코드 후보(`cc704e6f`)의 수용 결과를 그대로 쓴다. 새 squash SHA에서는 accept 설치 스모크(`fresh` 흐름의 A1·A2·W1-AB·W1-G·N1-ACCEPT·C1·A6·M4)를 한 번만 하고, 모두 PASS이고 남은 자원이 없고 prod가 그대로일 때 태그를 만든다. 제품 코드가 바뀌면 이 결정은 적용되지 않는다.
2. **수용 harness는 저장소에 둔다.** 위치는 `acceptance/harness/`다. `.github`+`scripts` 2,000줄 상한(SC7)에 넣지 않는다. 실행 상태 파일(사용자 답·실행 입력 묶음·승인)은 저장소에 넣지 않고 Git common-dir의 실행 사본에 둔다.
3. **업데이터 미확인 공개.** 1.0.0은 공개 버전 사이의 앱 안 업데이트를 실제로 실행하지 않은 채 공개하고 릴리스 노트에 적는다. 1.0.1을 내기 전에 accept 채널의 fixture 업데이트를 harness로 실행한다.
4. **범위 동결.** API·웹훅·변환 도구(D3의 F·G)는 1.0.0부터 결함 수정만 한다. 새 기능은 사용자가 요청할 때만 더한다. Windows에서 실행(`target = "windows"`)은 실험 기능으로 표시한다. D5("정말 쓸 일이 없을 것만 뺀다")는 이미 들어간 기능을 빼지 않는다는 뜻으로 유지한다.
5. **기록 간소화.** 문서 전용 커밋(`code=false`)은 검증한 소스 SHA를 바꾸지 않는 것으로 보고 같은 브랜치에 바로 커밋한다. 열린 후속은 1.0.0 기록 PR에서 GitHub 이슈로 옮기고, PROGRESS §4에는 [차단] 항목과 이슈 링크만 둔다.

결과: 01-design §0의 D3·D5는 그대로이고 1.0.0 뒤의 적용은 결정 4를 따른다. CONVENTIONS §5·§8·§9·§11이 결정 2·4·5를 담는다. 2026-11-05의 "보류: Windows 확인 뒤"는 결정 1의 확인으로 닫는다. 공개 뒤 사용자 실사용에서 나온 문제를 1.0.x의 우선순위로 삼는다. 제품 코드의 줄 수 상한(파일 600줄·컴포넌트 300줄)과 PROGRESS 200줄, I1 차단은 이 결정으로 바뀌지 않는다. harness 폴더에는 600줄을 넘는 파일이 있다: 실행한 사본과 바이트가 같아야 해서 그대로 들여온 기록된 예외이고(유지보수 판단이며 사용자 결정이 아니다), 나누기는 후속이다. 태그 push와 GitHub Release 공개는 릴리스마다 명시 승인이 필요하다는 규칙(CONVENTIONS §8·§11)도 그대로다. 사용자의 2026-11-25 요청은 1.0.0 한 번에만 해당한다.

확인하지 못했거나 목표에 못 미친 채 공개하는 주요 항목(릴리스 노트에 적는다. 전체는 PROGRESS §3): 공개 버전 사이의 앱 안 업데이트, Windows 알림, opencode·pi 실제 도구 행, 콜드 스타트 목표 미달(SC2 3초, 실측 5.1초 1표본), PR CI 시간 목표 미달(SC7), codex 0.172.0에서 근거를 얻지 못한 Codex 화면 행, 턴이 끝난 작업의 화면에 뜬 대화상자가 '입력 대기'로 바뀌지 않는 것(H2X-FEEDBACK FAIL(b). 그 화면으로 보내는 지시는 거절된다).
