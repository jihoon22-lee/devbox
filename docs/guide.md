# 사용 안내

devbox 화면을 처음 쓰는 사람을 위한 안내다. 설치와 첫 실행은 [README](../README.md#설치와-첫-실행), 설정 파일은 [설정 파일 안내](config.md), 보안 범위는 [SECURITY](../SECURITY.md)에 있다. 화면에 쓰는 말은 [화면 용어](ui-terms.md)를 따른다.

## 화면 구성

왼쪽 막대에서 섹션을 고른다. 시작 화면은 마지막으로 연 섹션이고 처음에는 에이전트다. 바꾸려면 설정 → 일반의 "시작 섹션"을 쓴다.

| 섹션 | 하는 일 | 열기 |
|---|---|---|
| 에이전트 | 에이전트 작업을 시작하고 지켜보고 검토한다 | Ctrl+1 |
| 터미널 | 현재 프로젝트의 터미널을 탭과 분할로 쓴다 | Ctrl+2 |
| 실행 | 현재 프로젝트의 작업·서비스·예약을 돌리고 로그를 본다 | Ctrl+3 |
| 소스 | 현재 프로젝트의 파일을 편집하고 Git 변경·브랜치를 본다 | Ctrl+4 |
| 노트 | 노트와 일일 기록을 쓰고 활동 기록을 본다 | Ctrl+5 |
| 도구 | API 요청, 웹훅, 변환 도구, 개발 환경 점검 | Ctrl+6 |

- 설정은 막대 맨 아래에 있다.
- 위쪽 줄에는 프로젝트 이름(누르면 프로젝트 전환), 알림 센터, [명령·검색]이 있다.
- 아래쪽 상태 표시줄은 연결 상태와 에이전트·실행·포트·WSL·Git 요약을 보인다. 요약을 누르면 그 화면으로 간다.
- 하단 패널(`` Ctrl+` ``)은 터미널·로그·문제 탭이다.
- 창을 닫으면 트레이로 내려가 계속 실행된다. 완전히 끄려면 트레이 메뉴의 [종료]를 누른다. 저장하지 않은 문서나 API 변경이 있으면 끄기 전에 묻는다.

## 프로젝트

터미널·실행·소스는 현재 프로젝트를 기준으로 보여 준다. 에이전트는 모든 프로젝트의 작업을 한 목록에 모은다.

- 위쪽의 프로젝트 이름이나 Ctrl+Shift+O로 "프로젝트" 창을 연다. 이름이나 경로로 찾고 Enter나 클릭으로 고른다. 즐겨찾기한 프로젝트가 위에 모인다.
- 프로젝트가 없으면 [프로젝트 추가]를 누른다. "폴더에서"는 WSL의 후보 폴더를 보이고 경로를 직접 입력할 수도 있다. "Git 주소로"는 주소를 받아 `~/projects/<이름>`에 가져온다.
- 각 줄에는 제거(devbox 목록에서만 지우고 폴더와 파일은 그대로 둔다), 즐겨찾기, 시작 구성 실행, 외부 앱으로 열기가 있다. 시작 구성 실행은 프로젝트의 `.devbox/devbox.toml`에 `[launch]`로 터미널·에이전트·서비스를 적어 둔 때만 나온다. 외부 앱(VS Code·탐색기·Windows Terminal)은 Windows 앱에서만 열린다.
- 프로젝트 설정에 적힌 명령을 처음 실행하려 하면 "프로젝트 명령 실행 승인" 창이 경로와 명령 전체를 보인다. [명령 실행 승인]을 눌러야 실행한다. 경로나 설정 내용이 바뀌면 다시 묻는다([설정 파일 안내](config.md)).

## 터미널

- [새 터미널]은 기본 셸을 연다. [새 세션 ▾]는 설정한 터미널 프로필이나 "기존 zellij 세션에 붙기"를 연다.
- 탭을 오른쪽이나 아래로 나누면 칸마다 터미널이 하나씩 생긴다.
- 칸·탭이나 앱을 닫아도 세션은 계속 실행되고 목록에 남는다. 목록의 세션을 누르면 다시 열고, 끝내려면 ⋯ 메뉴에서 세션 끝내기를 고른다. ⋯ 메뉴에는 이름 바꾸기, 새 창으로도 있다. 벨이 울린 터미널은 목록과 탭에 표시된다.
- 에이전트 작업의 터미널은 이 목록에서 끝내지 않고 에이전트 화면에서 끝낸다.

## 에이전트 작업

에이전트 작업은 Claude Code·Codex·opencode·pi 같은 도구가 작업 폴더(git worktree)에서 하는 일 하나다. 도구는 [README](../README.md#에이전트-도구)에 있다.

1. **시작.** [새 작업]이나 Ctrl+Shift+N으로 연 창에서 제목, 프로젝트, 도구, 기준 브랜치, 지시문을 정하고 [시작]이나 Ctrl+Enter를 누른다. 기준 브랜치를 비우면 현재 브랜치다. "작업 폴더 만들기"를 켜 두면(기본) 작업 폴더와 `agent/` 아래 브랜치를 새로 만들고, 끄면 현재 체크아웃에서 실행한다. 프로젝트에 지시문 템플릿이 있으면 [템플릿: 이름] 버튼이 지시문을 채운다.
2. **지켜보기.** 목록은 입력 대기 · 실패 · 검토 대기 · 실행 중 · 준비 중 · 닫힘(24시간) 순으로 묶인다. [격자]는 열린 작업의 터미널을 한 화면에 모은다. Ctrl+Shift+J는 다음 입력 대기 작업으로 간다. 입력 대기·다음 지시 대기·실패가 되면 알림 센터에 올라오고, 그 작업을 보고 있지 않으면 Windows 알림도 뜬다. 목록 위에 "상태 알림이 연결되지 않았습니다"가 보이면 [연결 확인]으로 설정 → 에이전트의 점검 결과를 본다.
3. **지시.** 작업 상세 아래 입력란에 다음 지시를 쓰고 Ctrl+Enter로 보낸다. Enter는 줄바꿈이다. 에이전트가 터미널에서 선택을 기다리는 동안에는 보낼 수 없으니 [터미널 보기]로 가서 직접 답한다. 터미널이 끊겼으면 [재개]로 다시 연다.
4. **검토.** 상세의 탭은 터미널 · 변경 · 커밋 · 실행이다. "변경"은 기준 브랜치와 비교한 파일별 diff를 보인다. 파일마다 [봤음]을 누르고, 줄을 골라 [지시에 인용]으로 지시란에 붙인다. [더 보기]에는 [테스트 실행], [검토 시작], [새 창으로]가 있다. [테스트 실행]은 프로젝트에 `[agent] test`가 있을 때 쓰고, [검토 시작]은 작업을 검토 대기로 옮긴다.
5. **반영.** 작업 폴더를 만든 작업에만 다음 버튼이 있다. [기준 반영]은 에이전트 도구를 멈추고 작업 브랜치를 기준 브랜치 위로 옮긴다. 도구가 살아 있으면 확인 창이 먼저 뜬다. 옮긴 뒤 이어서 지시하려면 [재개]를 누른다. [병합]은 "병합 커밋", "커밋 하나로 합쳐 병합", "기준 위로 옮긴 뒤 병합" 중 하나로 기준 브랜치에 합친다. [PR]은 제목과 본문을 쓰게 한 뒤 PR을 만든다. WSL의 `gh` 로그인이 필요하다. 병합과 PR 앞에는 기준·브랜치·앞섬·뒤처짐을 보이는 확인 창이 뜬다. 충돌이 나면 [충돌 해결] · [해결 지시 보내기] · [되돌리기]가 나온다. 충돌 중에는 재개할 수 없으니 충돌을 풀고 `git rebase --continue`를 마치거나 [되돌리기]를 누른 뒤 재개한다.
6. **마무리.** 병합하거나 PR을 만들면 작업이 닫혀 24시간 동안 "닫힘" 아래에 남는다. 그 작업 폴더의 정리는 `[agents] cleanup_after_close`가 정한다([설정 파일 안내](config.md)). [더 보기] → [폐기]는 작업 폴더와 브랜치를 지운다. 병합하지 않은 커밋이나 커밋하지 않은 파일이 있으면 확인 창이 개수를 알려 준다. 작업 폴더 없이 만든 작업에는 [세션 끝내기]가 나온다.

## 서비스와 로그

실행 섹션은 현재 프로젝트의 서비스·작업·예약과, Docker가 있으면 컨테이너를 보인다.

- 정의는 프로젝트의 `.devbox/devbox.toml`이나 "이 PC에만" 저장한 것에서 온다. [작업 추가 ▾]의 "직접 추가"는 종류·명령·작업 폴더·실행 대상(WSL 또는 Windows)·저장 위치를 받는다. 저장 위치의 기본값은 "프로젝트 파일에 저장"이고 프로젝트의 `.devbox/devbox.toml`에 쓴다. "이 PC에만"을 고르면 이 PC에만 둔다. "자동 감지 제안"은 [명령 확인 후 추가]로 더한다. 파일 형식은 [설정 파일 안내](config.md)를 본다.
- 항목마다 [시작] · [중지] · [재시작]이 있고, 서비스·작업·예약에는 [수정]도 있다. 항목 이름을 누르면 오른쪽에 그 실행의 로그가 나온다. 서비스를 중지하면 10초 동안 [되돌리기]가 뜬다.
- 서비스가 도는 동안 그 정의가 없어지면(설정에서 지움, 브랜치 전환, 이름 변경) 그 실행은 서비스 아래 "정의 없는 실행"에 남는다. 이름을 누르면 로그가 나오고, [중지]로 멈춘다. 정의가 없으므로 [시작] · [재시작] · [수정]이 없고, 중지해도 [되돌리기]가 뜨지 않는다.
- 로그는 텍스트나 정규식과 스트림(stdout·stderr·system)으로 거르고 [필터 적용]을 누른다. [지난 로그 검색]은 이미 지나간 줄을 찾는다. 위로 스크롤하면 따라가기가 멈추고 [맨 아래로]가 나온다. [하단 로그에 고정]을 누르면 다른 섹션에서도 하단 패널의 로그 탭에서 본다.
- 목록 위의 [포트 목록] · [프로세스 목록] · [WSL 리소스]는 열린 포트, 프로세스, WSL의 자원 사용을 보인다.
- 실행에서 찾은 오류와 경고는 하단 패널의 "문제" 탭에 모인다.

## 노트와 검색

- 노트는 WSL의 노트 폴더(기본 `~/notes`)에 있는 Markdown 파일이다. 위치는 `[notes] vault`로 바꾼다([설정 파일 안내](config.md)).
- 노트 목록은 "폴더" · "태그" · "활동" 탭이다. [새 노트]와 [일일 기록] 버튼이 목록 위에 있고 단축키는 Ctrl+N과 Ctrl+Alt+D다. Ctrl+Alt+D는 다른 섹션에서도 오늘의 일일 기록을 연다.
- 노트는 고치면 자동으로 저장한다. 헤더에 "저장됨 14:03"처럼 보이고, 연결이 끊기면 "연결 끊김 · 이 기기에 임시 저장", 저장이 부딪히면 "충돌 · 비교 필요"가 보인다.
- 헤더의 [미리보기 분할] · [백링크] · [새 창으로 열기]를 쓴다. [오늘 한 일 넣기]는 그날의 내 커밋, 닫은 에이전트 작업, 실패한 실행·예약을 오늘 일일 기록에 넣는다.
- 목록의 ⋯ 메뉴는 이름 바꾸기 · 새 창으로 열기 · 휴지통으로 옮기기다. 휴지통으로 옮기면 10초 동안 [되돌리기]가 뜬다.
- 빠른 캡처는 전역 단축키 Ctrl+Alt+N으로 작은 창을 열어 한 줄을 적고 Enter를 누르면 받은 글 노트(inbox)에 덧붙는다. Shift+Enter는 줄바꿈, Esc는 숨기기다.
- 통합 검색(Ctrl+Shift+F)은 노트 · 코드 · 파일 이름에서 찾는다. 범위를 고르고 "정규식"과 "대소문자 구분"을 켤 수 있다.

## 활동 기록

활동 기록은 꺼져 있다. 켜면 Windows에서 앞에 있는 창의 앱 이름과 제목을 기록하고, 제목은 개인정보 규칙을 적용한 뒤에만 보낸다([SECURITY](../SECURITY.md)).

- 설정 → 일반이나 설정 → 활동에서 [활동 기록 켜기]를 누른다. [일시중지]와 [활동 기록 끄기]도 같은 곳에 있고, 트레이 메뉴의 [활동 기록 일시중지]로도 멈춘다.
- 노트 목록의 "활동" 탭에서 날짜를 고른다. "일"은 총 시간·시간대별·앱별·프로젝트별, "주"는 날짜별·앱별·프로젝트별 시간을 보인다.
- 설정 → 활동의 "개인정보 규칙"에서 제외할 앱 이름, 제목 제외·가림 정규식, "모든 창 제목 숨기기", 유휴로 전환할 시간(분)을 정한다. 같은 곳에서 CSV나 JSON으로 내보낸다.

## 설정과 진단

| 탭 | 내용 |
|---|---|
| 일반 | Windows 시작 시 실행, 활동 기록, 테마, UI 배율(90–150%), 터미널 글꼴 크기(9–28), 시작 섹션 |
| 노트 | 노트 위치를 바꾸는 방법(`[notes] vault`)과 템플릿 목록 |
| 활동 | 활동 기록 켜기·끄기, 개인정보 규칙, 내보내기 |
| 에이전트 | 도구 프로필, 도구·상태 알림 점검, [셸 환경 다시 읽기], 현재 프로젝트의 정리 후보 |
| 비밀 | 비밀 이름·값, [복구 문자열 보기], [복구 문자열 입력] |
| 단축키 | 전역 단축키(Windows 앱)와 앱 단축키 목록 |
| 앱 진단 | 점검 결과, 지원 번들, [다시 설정], [WSL 쪽 정리] |
| 정보 | 앱 업데이트, 데몬 정보 |

연결이 안 되거나 도구를 못 찾으면 설정 → 앱 진단을 먼저 본다.

- 점검 목록은 tmux·git·gh·에이전트 도구 같은 WSL 쪽 환경을 보이고 고칠 방법을 적는다. [점검 새로고침]으로 다시 읽는다. 도구를 새로 설치했다면 [셸 환경 다시 읽기]를 누른다.
- 업데이트·제거·연결 화면 안내는 README의 [앱 업데이트](../README.md#앱-업데이트), [제거](../README.md#제거), [문제 해결](../README.md#문제-해결)을 본다.

## 단축키

Ctrl+Shift+P(또는 위쪽 [명령·검색])로 명령 팔레트를 연다. 명령 이름을 입력하고 ↑↓와 Enter로 고른다. 설정 → 단축키의 "앱 단축키"는 팔레트 명령에 붙은 단축키만 보인다. F1·Ctrl+K와 터미널 섹션의 Ctrl+Shift+E·D·W는 그 목록에 없고, 터미널 칸·편집기·입력란·API 요청·빠른 캡처 창의 키도 없다. 전체는 아래 표를 본다.

터미널이나 편집기에 포커스가 있으면 F1–F24, Ctrl+숫자, Ctrl+Shift+글자·Ctrl+Alt+글자만 앱이 받는다. 대화상자·메뉴·목록이 열려 있는 동안에는 앱 단축키가 동작하지 않는다.

| 단축키 | 동작 |
|---|---|
| Ctrl+Shift+P · Ctrl+K · F1 | 명령 팔레트 |
| Ctrl+1 – Ctrl+6 | 에이전트 · 터미널 · 실행 · 소스 · 노트 · 도구 열기 |
| Ctrl+Shift+O | 프로젝트 전환 |
| Ctrl+Shift+F | 통합 검색(터미널에 포커스가 있으면 터미널 검색) |
| Ctrl+Shift+N | 새 에이전트 작업 |
| Ctrl+Shift+J | 다음 입력 대기 작업 |
| Ctrl+Alt+D | 오늘의 일일 기록 |
| Ctrl+P | 파일 빠른 열기(프로젝트를 고른 뒤) |
| Alt+← · Alt+→ | 뒤로 · 앞으로(마우스 뒤로·앞으로 버튼도 같다) |
| Ctrl+Shift+B | 목록 영역 접기·펴기 |
| `` Ctrl+` `` | 하단 패널 열기·닫기 |
| Ctrl+= · Ctrl+- · Ctrl+0 | 화면 확대 · 축소 · 배율 초기화(터미널·편집기에 포커스가 없을 때) |
| Ctrl+Z | 최근 알림의 [되돌리기]. 입력란·터미널·편집기에 포커스가 없을 때만 된다 |

화면 안에서만 되는 단축키는 다음과 같다.

| 화면 | 단축키 | 동작 |
|---|---|---|
| 새 작업 창, 지시란 | Ctrl+Enter | 시작 · 보내기 |
| 터미널 섹션 | Ctrl+Shift+T · E · D · W | 새 터미널(탭) · 오른쪽 분할 · 아래 분할 · 칸 닫기 |
| 터미널 칸 | Ctrl+Shift+C · Ctrl+C(선택이 있을 때) | 복사 |
| 터미널 칸 | Ctrl+Shift+V | 붙여넣기 |
| 터미널 칸 | Ctrl+Shift+F | 터미널 검색(Enter 다음, Shift+Enter 이전, Esc 닫기) |
| 터미널 칸 | Ctrl+= · Ctrl+- · Ctrl+0 | 글꼴 크기 키우기 · 줄이기 · 기본값 |
| 터미널 칸 | `` Ctrl+` `` | 하단 패널 열기·닫기 |
| 노트 섹션 | Ctrl+N | 새 노트(편집기 밖에서) |
| 노트·소스 편집기 | Ctrl+S | 저장 |
| 소스 편집기 | Ctrl+F · Ctrl+H · Ctrl+G | 찾기 · 바꾸기 · 줄 이동 |
| 소스의 커밋 메시지 | Ctrl+Enter | 커밋 |
| 도구의 API 요청 | Ctrl+Enter · Ctrl+S · Ctrl+Shift+S | 보내기 · 저장 · 새 요청으로 저장 |
| 빠른 캡처 창 | Enter · Shift+Enter · Esc | 저장 · 줄바꿈 · 숨기기 |

전역 단축키는 devbox가 다른 창 뒤에 있거나 트레이에 있어도 동작한다. Windows 앱에서만 쓰고 설정 → 단축키에서 바꾼다. Ctrl·Alt·Shift 중 하나를 넣어야 하고 서로 달라야 한다. 등록하지 못하면 이유가 그 자리에 표시된다.

| 전역 단축키 | 기본값 | 동작 |
|---|---|---|
| 명령 팔레트 | Ctrl+Alt+Space | devbox 창을 앞으로 가져와 명령 팔레트를 연다 |
| 빠른 캡처 | Ctrl+Alt+N | 빠른 캡처 창을 연다 |
| 하단 터미널 | 없음 | 하단 패널을 열고 터미널에 포커스를 준다(터미널 탭이 선택돼 있을 때). 창이 이미 앞에 있고 패널이 열려 있으면 창을 숨긴다 |

## 명령줄

`devbox` 실행 파일은 WSL의 `~/.local/share/devbox/bin/devbox`에 있다. 앱이 시작할 때 배치한다. 아래 명령은 WSL 터미널에서 이 경로로 실행한다. accept 채널은 `~/.local/share/devbox-accept/bin/devbox --instance accept …`를 쓴다.

| 명령 | 하는 일 |
|---|---|
| `devbox doctor [--json]` | 환경을 점검한다. 점검마다 한 줄(상태·ID·메시지·고칠 방법)을 쓰고, `--json`이면 JSON 하나를 쓴다. 실패가 하나라도 있으면 종료 코드가 0이 아니다 |
| `devbox note add [--daily] "<글>"` | 받은 글 노트(inbox) 끝에, `--daily`면 오늘 일일 기록 끝에 글을 덧붙이고 그 파일 경로를 쓴다. 공백이 있으면 따옴표로 묶는다 |
| `devbox secrets export-key` | 복구 문자열을 표준 출력에 쓴다 |
| `devbox secrets import-key` | 표준 입력을 끝까지 읽어 복구 문자열로 키를 복구한다(붙여 넣고 Enter, Ctrl+D) |

- `note add`와 `secrets`는 WSL의 devbox에 연결해서 일한다.
- 복구 문자열은 비밀 값을 푸는 키 자체다. 설정 → 비밀의 [복구 문자열 보기]·[복구 문자열 입력]과 같은 일이다. 입력은 1024바이트까지 받고 `-`와 공백은 무시한다. 그 키를 쓰는 `devbox.db`가 아니면 거절한다([README](../README.md#백업과-다른-pc로-옮기기)).
- `devbox mcp`는 [README](../README.md#mcp)를 본다.
