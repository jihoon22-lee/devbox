## Table and file inventory

Imports use the fixed legacy app-local identifiers, WAL-consistent online backups
and a private unselected destination generation. Sources are opened read-only and
are not upgraded in place. All three selected stores must validate before one
generation pointer changes. Original snapshots and user files remain available.

| Source | Classification and fields | Destination treatment |
|---|---|---|
| Knowledge `settings(key,value)` | Authoritative vault binding, capture/UI preferences and other bounded settings; `wikilink-schema` is derived. | Preserve bounded user keys, remap the fresh vault binding only after owner approval; existing destination keys win. Retire only fixed derived/product-control keys. |
| Knowledge `note_templates(id,name,content,created_ts,updated_ts)` | Authoritative user templates. | Existing template validator applies. Preserve timestamps/content, map IDs, report name/content conflict and keep destination edits/deletions on repeat import. |
| Knowledge vault Markdown and image assets | Authoritative external files and relative links. | Keep their path and bytes in place. Import creates no note and copies no vault. Separate explicit note operations retain atomic writes, content-addressed images, bounded link resolution and rename all-or-rollback limits. |
| Knowledge `docs`, `docs_fts` and FTS shadow tables, `doc_link_keys`, `wikilinks` | Derived content/link index. | Do not import old index rows into the new owner. Rebuild independently after binding; partial/offline scans preserve last-good rows. Templates/settings are never cleared with the index. |
| Life Log `sessions(id,app,title,start_ts,end_ts,duration_ms)` | Authoritative activity history. | Validate intervals/counts and preserve rows with receipt-based ID mapping. Existing privacy and export sanitizers remain in the Activity owner. |
| Life Log `settings(key,value)` | Authoritative privacy, retention, idle threshold and project paths; product collection consent is installation-specific. | Preserve user preferences and old path attribution. Do not restore product collection consent. Registry association is a separate projection, never a destructive rewrite of old activity IDs. |
| Life Log `knowledge_draft_history(id,handoff_id,kind,status,summary_json,sources_json,created_ts,updated_ts,expires_ts,regenerated_from)` | Authoritative delivery history, with transient pending delivery state. | Validate exact DTO/bounds; remap history references. Convert pending/sent state to valid expired history and never replay a delivery. |
| Older Activity Timeline profile | Separate legacy input, previously absorbed by standalone Life Log. | B03 reads only the supported Life Log source. A remaining independent old profile is not claimed imported; B08 must surface this unsupported input. |
| Everything+ `roots(id,path,content)` | Authoritative root selection and per-root content policy. | Normalize identity without probing a stopped distro; map roots into the destination namespace. Preserve overlapping roots and deepest-root ownership. |
| Everything+ `saved_queries(id,name,query,filter_json,created_at,updated_at)` | Authoritative saved query/filter definitions. | Apply the real saved-query validator. Remap `sourceRootId`; reserve tombstones for references to deleted roots so later roots cannot acquire those references. Existing destination changes win on repeat import. |
| Everything+ `meta.schema_version`, `root_ownership_version` | Schema/derived ownership markers. | Accept known v0.7 schema/ownership version 2. Future versions block import without altering originals. |
| Everything+ `meta.next_root_id` | Authoritative allocator state in the old namespace. | Validate a positive integer; allocate from the destination's own monotonic sequence and source-to-destination receipts, including deleted referenced roots. Do not copy an old number over an active destination allocator. |
| Everything+ `meta.{pdf,docx,xls,xlsx,ods}_extractor_version` | Derived extractor markers. | Accept the pinned v0.7 `pdf-v1`/`docx-v1`/`xls-v1`/`xlsx-v1`/`ods-v1` markers and rebuild under current destination extractors. Do not mark newly imported content as already indexed. |
| Unknown Everything+ metadata | Unclassified possible user/future state. | Reject the unsupported inventory; retain the source and destination. No silent deletion or unsupported-success report. |
| Everything+ `files`, `files_fts`, `file_content`, `file_content_fts` and FTS shadow tables | Derived filename/content index. | Rebuild imported roots asynchronously; keep existing destination last-good index. Fixed sensitive-file exclusions and bounded text/document extractors stay in the original engine. |
| Collector handles, watcher queues, live queries, regex workers, preview tokens and WebView runtime state | Transient execution state. | Do not import. Start fresh bounded owners; show unavailable/indexing/expired states. Browser localStorage is not claimed migrated by the SQLite importer. |

`knowledge_import_rows_v1` records source/table/ID, fingerprint and destination ID.
An unchanged source row does not resurrect a destination deletion. A changed source
or destination is a conflict, not permission to overwrite. Unsupported tables,
oversized values, cancellation and future manifests leave the selected generation
unchanged. Database rollback does not undo user Markdown edits or promise vault
power-loss recovery. Switching back refuses newer authoritative destination edits.

## WSL and host limits

Portable tests cover UNC normalization/case-sensitive tails, partial scans,
last-good preservation and independent source budgets. Actual Windows→Ubuntu
WSL2 execution from `fb7d37e` passed Notes atomic/case/alias/unavailable/reconnect,
500-file Search/FTS/last-good/reconnect, and opaque source object/cancellation
checks. Three source/digest-verified Windows test executables use only a marked
`/tmp/devbox-knowledge-wsl2-fixture-<UUID>` and an in-memory index; no app startup,
legacy database or user vault runs. Evidence was preserved and owned folders
removed. WSL2 VM stop/suspend is not part of that proof.

The hosted fixture prepares a dedicated Ubuntu WSL1 distro from Canonical's
fixed 24.04 LTS rootfs and published SHA256. Its current execution passed vault
approval/case/atomic edits, 500-file source queries, alias identity and escaping
symlink rejection. The active-vault directory rename returned EPERM. The revised
fixture uses an independent Search corpus for root unavailability and polling
reconnect, and checks that Notes and a local source remain usable. That revised
hosted scenario still requires execution. A large query may publish complete
cached coverage with only a subset of native objects verified within 1.5 seconds;
exact queries check usable references without expanding the deadline.

Setup/cleanup refuse non-hosted environments and unregister only the exact
per-run registration/owner marker. The local WSL2 runner uses an ephemeral
process-only PowerShell policy override for the reviewed script; it changes no
persistent host policy. User profiles are never fixtures and the local Ubuntu
session is neither terminated nor reconfigured.
