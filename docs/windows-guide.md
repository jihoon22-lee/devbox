# Windows 설치·복구

[GitHub Releases](https://github.com/jihoon22-lee/devbox/releases)에 실제 공개된 버전을 선택한다.
v0.8 소스/후보/공개 상태는 [#541](https://github.com/jihoon22-lee/devbox/issues/541)에 구분해 기록한다.
Windows 11과 WebView2가 필요하다. 일반 사용자는 Rust·Node·MSVC를 설치할 필요가 없다.

## 설치와 portable

Suite 설치 파일 `Devbox_0.8.0_x64-setup.exe`는 Workspace·API Studio·Knowledge·Control Center를
함께 설치한다. 독립 실행이 필요하면 해당 제품 ZIP 전체를 별도 폴더에 푼다. 실행 파일만
옮기면 필수 component와 installation identity가 빠진다. 서로 다른 portable과 설치본은
각자의 namespace/identity로 취급하며 임의 경로를 Suite 구성원으로 자동 등록하지 않는다.

## 새 설치 활성화

새 설치는 설치 후 Control Center의 데이터 및 복구 화면에서 활성화를 확정한다.
네 제품을 열어 저장소를 준비하고 상태 기록을 확인한다.

## 백그라운드 서비스

설치된 Suite는 창 없는 `devbox-agent`가 작업·서비스·예약 실행, Webhook 리스너,
동의한 활동 기록과 검색 색인을 유지한다. 제품 창을 닫으면 제품 UI 프로세스가 종료되고
백그라운드 작업은 계속된다. Knowledge는 미저장 노트의 저장·버리기·취소 확인을 유지한다.
API Studio는 선택한 닫기 정책이 “리스너 중지”이면 리스너도 중지한다.

알림 영역의 Devbox 아이콘 하나에서 네 제품을 열거나 활동 기록을 일시중지/재개하고,
“백그라운드 작업 모두 멈추고 종료”로 모든 owner를 정리할 수 있다. 종료 뒤 열린 제품의
주기적 조회가 서비스를 다시 띄우지는 않는다. 화면의 수동 재연결 또는 새 제품 실행으로 시작한다.

Control Center의 환경 또는 Knowledge의 활동 설정에서 “로그인할 때 백그라운드 서비스 시작”을
켠다. 같은 설정이며 기본은 꺼짐이다. 로그인 시 제품 창은 열리지 않고, 활동 수집은 별도의
동의가 있어야 한다. 기존 설치의 제품 자동 시작은 agent 등록 하나로 이전한다. 다른 설치가
자동 시작을 사용 중이면 해당 설치에서 먼저 꺼야 한다.
자동 시작 명령이 [Windows Run의 260자 한도](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)를
넘는 설치 경로에서는 켜기를 거부한다. 다른 기능과 업데이트는 계속 사용할 수 있고 기존 등록은 보존한다.

portable 제품은 UI와 엔진 수명이 함께하며 agent 트레이·로그인 자동 시작을 지원하지 않는다.
실제 공개 버전의 지원 범위는 해당 Release 설명을 확인한다.

## Workspace 에이전트

WSL 프로젝트를 선택하고 **에이전트**에서 제목과 도구(Claude Code·Codex·직접 입력)를
선택한다. 도구는 해당 WSL 배포판에 설치되어 있어야 한다. 기본 작업 폴더 옆에 별도
worktree와 `agent/…` branch를 만들고, 새 터미널 창에서 선택한 명령을 한 번 실행한다.
기본 폴더의 Git 설정을 아직 승인하지 않았다면 **소스 화면 열기**에서 확인한 뒤
**다시 시도**한다. 새 작업 폴더의 Git 설정 승인은 별도이며 자동으로 이어받지 않는다.

**터미널 보기**로 실행 창을 열고 **변경 검토**로 해당 작업 폴더의 Source 화면을 연다.
터미널 종료 뒤에는 **터미널 다시 열기**를 선택할 수 있다. 터미널 레이아웃을 일반 프로필로
저장하면 다음 실행 때 명령 확인을 다시 묻고, 복원 전용 창에서는 명령을 자동 실행하지 않는다.

변경을 커밋한 뒤 **병합**을 누르면 기본 폴더의 현재 branch를 표시한다. 확인하면 merge
commit으로 병합하며 기본 폴더에 미커밋 변경이 있으면 거부한다. 충돌은 병합을 되돌리고
파일 목록을 표시한다. 성공 후 **정리**하면 터미널을 종료하고 병합된 작업 폴더와 branch를
삭제한다. **버리기**는 화면 안 확인 후 미커밋 변경까지 삭제하므로 필요한 변경을 먼저 보관한다.
끝난 작업의 **목록에서 지우기**는 작업 기록만 지운다.

응답을 받지 못했으면 목록을 다시 읽고 재시도한다. 이 설치에서 생성을 요청한 기록이 있고
기존 Git 기록의 경로와 branch가 정확히 일치할 때만 작업을 이어간다. 첫 생성 요청에서 이미
존재하던 작업 폴더는 자동으로 가져오지 않는다. 정리가 일부만 끝나 branch가 남았거나 폴더가 다른
branch를 가리키면 자동으로 삭제하지 않는다. Source에서 상태를 확인한다.

에이전트 화면의 CPU·메모리·프로세스 수는 실행 중인 작업의 현재 폴더와 하위 폴더를 기준으로
10초마다 읽는다. CPU 100%는 한 코어이며 첫 표본이나 프로세스 재시작 직후에는 **측정 중**으로
표시한다. 화면이 숨겨지면 주기 조회를 멈춘다. 터미널을 종료해도 그 폴더에 남은 다른 프로세스가
있으면 해당 사용량은 계속 표시될 수 있다.

**토큰 사용량 보기**를 누르면 해당 WSL 사용자의 Claude Code·Codex 기록에서 입력·출력·캐시를
집계한다. 자동으로 기록을 계속 읽지 않는다. Claude 반복 메시지는 한 번만, Codex 세션은 마지막
누적값만 센다. 파일 256개·합계 128MiB·줄당 4MiB·Codex 최대 31일 범위를 넘거나 일부를 읽지
못하면 **일부 기록만 읽었습니다.**를 표시한다. 도구의 기록 형식이나 기록 여부에 따라 실제 사용량과
차이가 날 수 있다.

## AI 도구 연결(MCP)

설치형 Suite의 **Control Center → 환경 → MCP 서버**에서 **MCP 서버 사용**을 켠다.
기본은 꺼짐이며 portable에서는 지원하지 않는다. 프로젝트·작업·실행 이력·로그·검색·노트
읽기를 AI 도구에 제공한다. **노트 기록 허용**과 **신뢰한 작업 실행 허용**은 별도로 켠다.
노트 기록은 현재 vault의 `Inbox/`에 새 파일만 만들며 기존 노트를 덮어쓰지 않는다.
작업 실행은 Workspace에서 승인한 작업만 가능하고 원본·승인을 실행 직전에 다시 확인한다.

Claude Code는 화면의 **Claude Code 등록 명령 복사**를 눌러 WSL 터미널에서 실행한다.
명령은 `claude mcp add --scope user devbox -- … --mcp-stdio` 형식이며 `wslpath -u`로
실제 설치 경로를 변환한다. 이후 Claude Code의 `/mcp`에서 연결 상태를 확인한다.

Codex는 **Codex 설정 복사**의 `[mcp_servers.devbox]` 블록을 WSL의
`~/.codex/config.toml`에 추가한다. `command`는 `/mnt/c/…/bin/devbox-mcp.exe`,
`args`는 `["--mcp-stdio"]` 형식이다. 기본 자동 마운트 위치를 바꿨다면 `wslpath -u`로
변환한 실제 경로를 사용한다. 고정 `bin/devbox-mcp.exe` 경로이므로 generation이 바뀌어도
등록 명령을 다시 고칠 필요가 없다.

읽기 도구는 `devbox_projects`, `devbox_tasks`, `devbox_runs`, `devbox_run_log`,
`devbox_search`, `devbox_note_read`다. 쓰기 권한을 켜면 각각 `devbox_note_capture`,
`devbox_task_run`도 나타난다. 목록은 최대 50개, 검색은 20개, 로그는 64KiB, 노트 읽기는
256KiB로 제한한다. 노트 폴더나 검색이 준비되지 않았다면 Knowledge를 열어 설정한다.

**MCP 서버 사용**을 끄면 다음 호출부터 도구 사용이 차단된다. 새 연결에는 Control Center에서
켜라는 안내가 나오고 열린 연결의 도구 목록은 비워진다. 쓰기 권한을 끄면 해당 쓰기 도구만
목록에서 빠지고 실행도 거부된다.

## 업데이트와 복구

Control Center의 review에 표시된 generation과 변경 내용을 확인한 뒤 적용한다. commit 전 undo는
이전 활성 generation으로 돌아가며, data restore는 검토한 경계를 따른다. commit 후 생성한 새
데이터를 과거 backup으로 조용히 덮어쓰지 않는다. 잠긴 파일·권한·공간 부족·중단은 실패 상태와
journal을 남기며 재개/복구 UI에서 처리한다. 복구가 끝나기 전에 설치 폴더를 수동으로 지우지 않는다.

제거는 설치가 소유한 파일·등록만 대상으로 하고 네 제품 사용자 데이터를 보존한다.
외부에서 만든 실행 파일 절대경로 shortcut이나 script는 새 제품 경로로 직접 수정한다.

## API Studio 가져오기

Requests의 컬렉션 영역에서 **가져오기**를 열어 curl 명령을 붙여 넣거나 Postman v2.0/v2.1,
Insomnia v4, HAR, Bruno `.bru`, Devbox JSON 파일을 선택한다. 파일 형식은 자동으로 판별하거나
직접 지정할 수 있다. Bruno는 여러 파일을 함께 선택할 수 있다. 파일은 하나당 16 MiB,
전체 32 MiB·500개 이내여야 한다.

미리 보기에서 폴더별 요청을 선택하고 **선택한 N개 가져오기**로 저장한다. 환경 변수는
**환경도 가져오기**를 켠 경우에만 추가된다. 인증·비밀 값은 안전한 참조나 마스킹 값으로
변환되며 **비밀 검토 필요** 항목은 보내기 전에 확인한다. 비밀 환경 변수는 값을 다시
입력해야 한다. 외부 스크립트·테스트·플러그인은 실행하지 않고 경고로 표시하며, 요청이
참조한 로컬 파일도 읽지 않는다.

가져온 직후 8초 동안 **되돌리기**를 사용할 수 있다. 그 사이 저장 내용이 바뀌면 이후
변경을 보호하기 위해 되돌리지 않는다. 파일 컬렉션의 양방향 자동 동기화는 지원하지 않는다.

### 파일 컬렉션

**폴더로 내보내기**는 빈 폴더 또는 이전에 Devbox에서 내보낸 폴더에
`collection.devbox.json` 표시 파일과 요청별 `.request.json` 파일을 쓴다. 컬렉션의 폴더 구분은
하위 디렉터리로 유지된다. 이 파일들을 Git 저장소에 커밋하면 요청 변경을 diff로 검토할 수 있다.
인증 값은 환경 변수 참조로 두고, 내보내기에서 가려진 비밀은 가져온 앱에서 다시 설정한다.

다시 내보낼 때 목록에서 빠진 옛 요청 파일은 지우지 않고 남은 파일 목록을 안내한다.
필요 없는 파일은 내용을 확인한 뒤 직접 정리한다. **가져오기 → 폴더에서**로 Devbox 파일
컬렉션이나 Bruno 컬렉션 폴더를 읽고 같은 미리 보기에서 선택해 가져올 수 있다.
폴더 선택은 10분 동안 유효하며, 링크·junction을 통한 외부 경로 접근은 허용하지 않는다.
폴더 가져오기는 깊이 8·파일 1,000개·파일당 1 MiB·합계 32 MiB 이내다.
