## SC2 — native app instrumentation log

The installed Windows app writes these lines to its stderr; capture them from an owned launch. Every interval is measured on the app process's monotonic `Instant`, never by subtracting renderer `performance.now()`/`Date.now()`, and includes the renderer's acknowledgement IPC return, so each value is a conservative upper bound. `run=` is the app process ID and binds samples to one process run.

- `palette-painted run=… trace=N outcome=painted deferred=false elapsed_ms=…` — global shortcut received natively → palette open state committed and two animation frames presented. Only these samples, taken while the app is tray-resident with the shell connected, count toward ≤300ms; a request queued natively before the shell listens (startup, gate not ready, reconnect) is not distinguished and includes that wait. `deferred=true` means the request waited behind another dialog and its elapsed time includes that wait; `outcome=already-open` means the palette was already open and the request was consumed. `outcome=stale`/`unknown` lines are ignored acknowledgements without elapsed time. `palette-trace-dropped` reports a trace evicted from the 16-entry bounded store. Tray/menu opens carry no trace and log nothing.
- `first-data-painted run=… elapsed_ms=… visible=…` — earliest point of the Rust `run()` (OS loader time before Rust `main` excluded) → the agent list, or its empty state, rendered from daemon data and two animation frames presented. This is logged once per process. Transport/gate readiness never produces it. Run with start section 에이전트, or the default start section "last" with last section `/agents` (also its fallback when none is saved), and do not interact before the line appears. `visible=false` (for example a `--minimized` autostart launch) is not a visible cold-start sample.

Record repetitions, cold/warm and WSL running/stopped conditions with the raw lines. Do not shut down the host WSL to obtain a stopped sample; that uses the isolated environment named in 07c §14.
