Task 24 SC10 instrumentation is a separately built artifact. It adds no product debug API and uses each window's existing production `RpcClient`, found in React provider props. Browser/gateway timings and percentile sums cannot establish the Windows full-path criterion.

Build from the same source SHA as the installed Windows CI artifact:

```sh
pnpm --filter app exec vite build --config acceptance/vite.config.ts
```

Launch the owned installed Windows app with **per-process** `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=<owned-port> --remote-debugging-address=127.0.0.1`. Do not change global environment or attach to a user's existing app. Verify installation source SHA/hash as specified by 01-design §11. Create two owned native popout windows and inject `app/dist/acceptance/terminal-probe.js` into each via CDP `Runtime.evaluate` (or Playwright CDP). `devboxSC10.findClient()` rejects browsers and the main window; failure to find a ready client is FAIL/missing evidence, never a partial-path PASS.

1. Window A: await `devboxSC10.echo(200)`. This timestamps `performance.now()` immediately before production `ClientStream.write(Uint8Array.of(byte))` and on receipt of that byte in `onData`, before ACK/drawing. Ten warm-ups are disclosed. Each sample traverses frontend → Tauri IPC/mux → Windows `wsl.exe` bridge → daemon PTY → tmux → return. The fixture uses raw, non-echo input and rewrites one cell, cycling ASCII q/z/w/b. Report raw samples, p50 ≤10ms and p95 ≤25ms.
2. Window A: await `devboxSC10.beginFlood()` (creates and attaches an owned terminal; waits for readiness).
3. Window B: start `devboxSC10.pingUntilStopped()` and retain its promise without awaiting it yet. Each ping is timed in B, through B's own native client/channel.
4. Window A: `devboxSC10.startFlood()`, then await `devboxSC10.finishFlood()`. A raw-input Python fixture writes exactly 100,000,000 bytes, as fast as the PTY/tmux path can consume them, without producer pacing. The completion marker comes after producer output; the next one-byte echo must return within 1000ms. tmux repaint bytes do not equal producer bytes and are not used as a byte-count claim.
5. Window B: `devboxSC10.stopPings()`, await the retained promise. Pass its samples and A's `started`, `finished`, `recoveryMs` to `devboxSC10.floodVerdict(...)`. Every ping request started during A's output interval is eligible, including responses arriving after output finishes; await the retained promise after `stopPings()` to retain the outstanding response. at least 20 are required and p95 must be ≤100ms. Preserve raw samples in the evidence. Insufficient concurrent samples must be reported as failed/missing evidence; do not slow the producer to obtain a PASS.
6. On failure call `devboxSC10.cleanup()` in A, `stopPings()` in B, then close only the owned popouts. Cleanup records only terminal IDs created by this tool. It never kills the daemon/tmux server or stops shared units. Preserve cleanup failures/IDs as FAIL evidence.

CDP commands occur outside the measured byte and ping intervals. Actual measurements require the installed Windows app, tmux, Python 3, and its live WSL bridge. Linux `terminal_latency.rs` provides a separately labeled partial-path diagnostic; it cannot replace this Windows measurement. Preserve source SHA, Windows artifact provenance/SHA256, window labels, transport/instance, raw samples, and PASS/FAIL/missing results in PROGRESS/PR artifacts.
